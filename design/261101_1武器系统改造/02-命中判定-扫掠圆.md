## 一句话：整段代码只做一件事

**把一条几何陈述，改写成一条代数方程，好让求根公式能用。**

```
|p(t) − c|² = rr²          几何陈述：某一时刻，弹丸到圆心的距离恰好等于 rr
        │
        │  把 p(t) = p0 + t·d、f = p0 − c 代进去，展开点积
        ▼
A·t² + B·t + C = 0         代数方程：t 的二次多项式
        │
        │  求根公式
        ▼
t = (−B ± √(B² − 4AC)) / 2A
```

第一行说得对，但**解不出来**——`t` 埋在向量 `p(t)` 里、又埋在范数里，求根公式只认多项式。
第三行才是能算的形式。

中间出现的 `rr`、`d`、`f`、`a`、`b`、`cc` **全部只是为了完成这一次改写而引入的中间量**。
它们不是新的条件，不是新的约束，也不构成第二个方程。

> 这就像把 `x + x + 1 = 5` 合并成 `2x = 4`：
> 你不会说「需要两条方程」，你只会说「我把左边合并了」。

---

## 1. 问题定义

一发弹丸，半径 `r`，在这一帧从 `p0` 移动到 `p1`。
一个目标，半径 `R`，圆心 `c`，这一帧视为静止。

问两件事：

1. 这一帧**有没有**撞上？
2. 如果撞上了，撞上的时刻在帧内的哪个位置？

时刻用归一化参数 `t ∈ [0, 1]` 表示：`t = 0` 是帧首，`t = 1` 是帧末。

> 为什么不逐帧做「点 vs 圆」测试？
> 因为会**隧穿**。dt = 1/60，弹速 900 时一帧走 15px，比单位半径（≈4.5）还大。
> 逐帧测试会直接从目标身上跳过去。扫掠判定用「线段」代替「点」，天然免疫。

---

## 2. 第一步：把「圆 vs 圆」化成「点 vs 大圆」

两个圆相交的充要条件是**圆心距 ≤ 半径之和**：

```
|P_弹 − P_目| ≤ R + r
```

把 `r` 挪到右边：

```
|P_弹 − P_目| ≤ (R + r)
```

这在几何上叫**闵可夫斯基和**（Minkowski sum）的一个特例：`圆 ⊕ 圆 = 圆`，半径相加。

**等价表述**：把弹丸缩成一个点，把目标膨胀成半径 `R + r` 的圆。判定结果完全不变。

于是整段代码只需要处理「点 vs 圆」，永远不需要处理「圆 vs 圆」。

**代码里的 `rr = R + r` 就是这个变换的产物。** 这是整段代码的灵魂——它不是"为了省事把半径加起来"，而是一次严格的等价变换。

---

## 3. 第二步：把线段参数化

```
p(t) = p0 + t · d        t ∈ [0, 1]
```

其中 `d = p1 − p0` 是这一帧的**位移向量**。

再定义 `f = p0 − c`：**帧首时，弹丸相对于目标圆心的位置。**

```js
const dx = p1.x - p0.x, dy = p1.y - p0.y;   // d
const fx = p0.x - c.x,  fy = p0.y - c.y;    // f
```

这两个向量就够了——后面所有量都由它们导出。

---

## 4. 第三步：写出相交条件

点在 `t` 时刻刚好落在圆边界上：

```
|p(t) − c|² = rr²
```

把 `p(t) − c` 展开成 `f + t·d`：

```
|f + t·d|² = rr²
```

> **注意：这不是两条方程，是同一条。**
> `p(t) − c` 和 `f + t·d` 是**同一个向量**，只是换了个名字：
> `(p0 + t·d) − c = (p0 − c) + t·d`，三项恒等，没有近似。
> 写第二遍的唯一目的，是把 `t` 从范数里挖出来，变成能套求根公式的多项式。
> 类比：`x + x + 1 = 5` 和 `2x = 4` 是同一条方程，不是两条。
> 代码里最终也**只有一条**：`a·t² + b·t + cc = 0`。前两行都只是它的「人话版本」。

展开点积：

```
(f + t·d)·(f + t·d) = rr²
f·f + 2t(f·d) + t²(d·d) = rr²
```

移项，整理成标准的二次方程 `a·t² + b·t + cc = 0`：

| 系数 | 代码 | 表达式 | 几何含义 |
|---|---|---|---|
| `a` | `dx*dx + dy*dy` | `d·d = \|d\|²` | 这一帧位移长度的平方。**必须 > 0** |
| `b` | `2*(fx*dx + fy*dy)` | `2(f·d)` | 位移方向与「弹丸→圆心」方向的点积 × 2 |
| `cc` | `fx*fx + fy*fy - rr*rr` | `\|f\|² − rr²` | 帧首距离平方减去半径平方 |

> **命名陷阱**：代码里叫 `cc` 不叫 `c`，因为 `c` 已经被「目标圆心」占用了。
> 但它**不是**标准形式的 `c`，而是标准形式的 `c/a` 里那个常数项。读的时候不要按二次方程的 ABC 套。

---

## 5. 第四步：判别式

```
disc = b² − 4·a·cc
```

| `disc` | 几何含义 | 处理 |
|---|---|---|
| `< 0` | 直线与圆**无交点** | `return -1` |
| `= 0` | 相切（擦边） | 一个根，算命中 |
| `> 0` | 两个交点：进入 + 离开 | 取**先发生的那个** |

```js
if (disc < 0) return -1;
```

注意这一步的严谨性：解出的是**无限长直线**与圆的交点。但线段是直线的子集，所以「直线无交点」⟹「线段无交点」，这个提前返回是安全的。

---

## 6. 第五步：为什么取 `−√disc`

求根公式：

```
t = (−b ± √disc) / (2a)
```

两个根对应两个时刻：**进入圆**和**离开圆**。

因为 `a = |d|² > 0`（二次项系数为正，抛物线开口向上），所以：

```
左根 (−b − √disc)/(2a)  <  右根 (−b + √disc)/(2a)
```

左根更小 = 时间更早 = **进入时刻**。

我们只关心「第一次撞上」，所以取左根：

```js
const t = (-b - Math.sqrt(disc)) / (2*a);
```

---

## 7. 四个分支逐条解释

### 7.1 起点已重叠 —— `return 0`

```js
if (fx*fx + fy*fy <= rr*rr) return 0;
```

**这不是一个优化，是正确性所必需的。**

反证：如果起点在圆内，则 `cc = |f|² − rr² < 0`。那么

```
两根之积 = cc / a < 0
```

两根**异号**。左根是负数 → 最后一行 `t >= 0` 会把它判掉 → 函数返回 `-1` → **漏判**。

所以必须单独处理。语义上：帧首就已经重叠，返回 `t = 0` 表示「这一刻就算命中」。

**为什么用 `<=` 而不是 `<`**：
如果起点恰好**在边界上**（`cc = 0`），两根是 `0` 和 `−b/a`。
- 若 `b > 0`，左根 = `−b/a < 0` → 同样会被判掉。
- 所以必须用 `<=` 把「贴边」也算进「已重叠」。

这个 `=` 是刻意的，不是手滑。

### 7.2 弹丸没有移动 —— `return -1`

```js
if (a < 1e-9) return -1;
```

`a = |d|²`。若 `a ≈ 0`，两个后果：
1. 后面除以 `2a` 会炸（除零 / 精度崩塌）。
2. 语义上：一个**完全静止**的弹丸不可能撞上任何东西——除非起点就重叠，而那种情况 7.1 已经处理了。

所以这里返回 `-1` 是正确的，不是「没考虑到的退化情形」。

### 7.3 无交点 —— `return -1`

见第 5 节。

### 7.4 线段范围外 —— 最后一行

```js
return (t >= 0 && t <= 1) ? t : -1;
```

这是「**线段**」与「**直线**」的分界，也是这个函数正确的关键：

| 情况 | 几何含义 | 处理 |
|---|---|---|
| `t < 0` | 交点在 `p0` 的**后方**——弹丸已经飞过目标，正在远离 | 不算命中 |
| `0 ≤ t ≤ 1` | 交点在这一帧的行程之内 | 命中 ✅ |
| `t > 1` | 交点在 `p1` 的**前方**——这一帧还走不到 | 下一帧再算 |

---

## 8. 返回值的用途

`t` 不只是个布尔值。它是**子帧时刻**，能撑起三件事：

**① 命中位置**

```js
const hx = p0.x + t * (p1.x - p0.x);
const hy = p0.y + t * (p1.y - p0.y);
```

爆炸必须发生在 `h` 处，**不是 `p1` 处**。否则高速弹的爆炸会往前窜一截，视觉和数值都对不上。

**② 穿透排序**

一发穿透弹这一帧可能同时命中 3 个目标。收集所有 `t`，**按 `t` 升序**排序，取前 `pierce + 1` 个——这就是「先打中谁」。

```js
const hits = candidates
  .map(o => ({ o, t: sweptHit(p0, p1, r, o, o.hitR) }))
  .filter(h => h.t >= 0)
  .sort((A, B) => A.t - B.t);
```

**③ 确定性**
`t` 是浮点数，同一帧内不同单位的 `t` 排序是稳定的。但若两个目标 `t` 完全相同（正面对齐），就需要加一个 tiebreak（按单位 id），否则结算顺序会随数组顺序抖动。

## 9. 完整代码

```js
/**
 * 扫掠圆判定：半径 r 的弹丸从 p0 走到 p1，是否撞上半径 R、圆心 c 的圆。
 * @returns {number} 命中时刻 t ∈ [0,1]；未命中返回 -1
 */
function sweptHit(p0, p1, r, c, R) {
  const dx = p1.x - p0.x, dy = p1.y - p0.y;
  const fx = p0.x - c.x,  fy = p0.y - c.y;
  const rr = R + r;                              // 闵可夫斯基和：圆 ⊕ 圆 = 圆

  if (fx*fx + fy*fy <= rr*rr) return 0;          // 帧首已重叠（含贴边）

  const a = dx*dx + dy*dy;                       // |d|²
  if (a < 1e-9) return -1;                       // 静止弹丸撞不到任何东西

  const b   = 2*(fx*dx + fy*dy);                 // 2(f·d)
  const cc  = fx*fx + fy*fy - rr*rr;             // |f|² − rr²
  const disc = b*b - 4*a*cc;
  if (disc < 0) return -1;                       // 无限长直线都无交点，线段更不会有

  const t = (-b - Math.sqrt(disc)) / (2*a);      // 取左根 = 进入时刻
  return (t >= 0 && t <= 1) ? t : -1;            // 裁到线段范围内
}
```

## 10. 验算

### 例 1：斜穿而过

| 量 | 值 |
|---|---|
| `p0` | `(0, 0)` |
| `p1` | `(100, 0)` |
| `r` | `2` |
| `c` | `(50, 10)` |
| `R` | `10` |

`rr = 12`，`d = (100, 0)`，`f = (-50, -10)`

```
a  = 100²                  = 10000
b  = 2·(-50·100 + -10·0)   = -10000
cc = (2500 + 100) − 144    = 2456
disc = 10000² − 4·10000·2456 = 1,760,000
√disc ≈ 1326.65
t = (10000 − 1326.65) / 20000 ≈ 0.4337
```

命中点 `(43.37, 0)`。反验：到圆心 `(50,10)` 的距离

```
√(6.63² + 10²) = √143.97 ≈ 12.00 = rr  ✅
```

### 例 2：恰好擦边（边界检查）

同上去掉 `R`，改 `R = 8` → `rr = 10`：

```
cc = 2600 − 100 = 2500
disc = 10000² − 4·10000·2500 = 0        ← 相切
t = 10000 / 20000 = 0.5
```

命中点 `(50, 0)`，到 `(50,10)` 距离正好 `10 = rr`。✅
`disc = 0` 走的是「一个根」的分支，代码不特殊处理也能正确得到 `t = 0.5`。

## 11. 已知局限

诚实列出，不建议现在解决：

**1. 假设帧内是直线运动。**
追踪弹在这一帧内是转弯的，严格应该用弧线扫掠。但 dt = 1/60、转向速率有限时，直线段近似足够。
若确需更准：把一帧拆成 `N` 个子步，每步调一次 `sweptHit`，取最小的 `t`。通常 `N = 2` 就够。

**2. 只处理圆。**
驱逐舰这种长条，用单圆会「头尾判小、腰部判大」。
解决办法（按复杂度递增）：
- **多圆胶囊**：一艘船 = 沿舰体中轴排 2–3 个圆，每个独立判定。简单、够用、天然支持「打中引擎区」这类扩展。
- OBB × 线段扫掠：数学多一维，收益有限。

**3. 不回答「谁先撞」。**
它只回答「我和这一个目标撞没撞」。多个目标要调用方自己收集、排序。

**4. 目标视为帧内静止。**
目标这一帧也在动（速度约 96 px/s，一帧 1.6px）。忽略它会带来最多 1.6px 的判定误差——远小于 `hitR`，可以接受。
要更准就对目标也做扫掠（相对速度法），但那会让 `p1` 的含义变复杂，不建议。

**5. 不做弹丸之间的碰撞。**
大群 RTS 不需要，且会破坏 flocking 的平滑感。

## 12. 调用方怎么写

```js
// 一帧的弹丸推进
for (const p of projectiles) {
  const p0 = { x: p.x, y: p.y };
  p.x += p.vx * dt;                       // 弹道随便算：直线 / 追踪 / 螺旋
  p.y += p.vy * dt;
  const p1 = { x: p.x, y: p.y };

  // 命中判定：只吃 p0 → p1，不吃「为什么这么走」
  const cands = grid.querySegment(p0, p1, p.contactR);
  const hits = [];
  for (const o of cands) {
    const t = sweptHit(p0, p1, p.contactR, o, o.hitR);
    if (t >= 0) hits.push({ o, t });
  }
  hits.sort((A, B) => A.t - B.t);

  for (const h of hits.slice(0, p.pierce + 1)) {
    if (squads[h.o.squad].faction === p.faction) continue;   // 友军
    // 命中点用 t 插值，不要用 p1
    const hx = p0.x + h.t * (p1.x - p0.x);
    const hy = p0.y + h.t * (p1.y - p0.y);
    applyDamage(h.o, p.dmg, p.shieldMul);
    if (p.blastR > 0) explode(hx, hy, p.blastR, p.blastDmg);
  }
}
```

注意最后两行的分工：`contactR` 决定「打没打中」，`blastR` 决定「打中之后波及多大」。**这两个参数现在是独立的**——这就是从「爆炸范围是唯一命中手段」里解放出来的那一步。
