# 01 · 现状诊断

## 1. 单位的数据契约里没有几何

`group-layer.js` 头部写明了契约：

```js
// unit { x, y, vx, vy, squad, alpha, cAll }
// squad { p:{...rRep, rOri, rAtt...}, faction, target, goal, cx, cy, cn }
```

`defense-system.js` 的 `initCombat` 又加了战斗字段：

```js
u.hp, u.maxHp, u.regen, u.shield, u.weapon, u.cd, u.charger, u.energy, u.castCd
```

**没有任何一个字段描述「这个单位有多大」。**

## 2. 但渲染里已经有半径了

这是最值得注意的一点——几何其实一直存在，只是没被提取成数据：

| 位置 | 代码 | 实际尺寸 |
|---|---|---|
| 本体箭头 | `moveTo(6.4,0) lineTo(-4.2,3.6)` | 长约 10.6px，半宽 3.6px |
| 护盾环 | `ctx.arc(u.x, u.y, 8.6, ...)` | 半径 8.6 |
| 血条 | `const bw = 13, bh = 2.2` | 宽 13 |
| 充能器标记 | `ctx.arc(u.x, u.y + 8.5, 1.9, ...)` | 偏移 8.5 |

**所以「受击体积」不是新增概念，是把渲染里已经在用的隐含尺寸提取成数据。**

参考值：`hitR ≈ 4.5`（箭头几何中心到边缘的等效半径）。

## 3. 三个耦合

### 耦合一：武器形状是封闭枚举

`weapon-system.js`：

```js
export const WEAPONS = {
  ray:      { shape: "rect",   width: 28, ... },
  laser:    { shape: "point",  ... },
  torpedo:  { shape: "circle", radius: 50, speed: 210, ... }
};
```

`stepWeapons` 里靠 `if (w.shape === "point") / ("rect") / ("circle")` 分三个分支。

**加一把枪 = 加一个枚举值 = 改这个 switch = 回归测试全部三个分支。** 这是硬编码的封闭集合，不是配置。

### 耦合二：命中判定吃的是点

`stepWeapons` 里所有判定的输入都是 `o.x, o.y`：

```js
// rect 分支
const rx = o.x - u.x, ry = o.y - u.y;
const perp = Math.abs(rx * uy - ry * ux);
if (perp > halfW) continue;

// circle 分支
if (dx * dx + dy * dy > r2) continue;

// point 分支
hits.push({ t: tgt, dmg: w.dmg, ... });   // 直接命中，没有判定
```

`point` 分支连判定都没有——因为锁定的是「最近的敌人」，直接就把伤害推给它了。

### 耦合三：没有空间索引

```js
// 找最近敌人：对每个单位遍历全部单位
for (let j = 0; j < n; j++) { ... }        // O(n²)

// 爆炸：对每个弹丸遍历全部单位
for (let j = 0; j < n; j++) { ... }        // O(n × m)
```

400 单位规模下，第一项是 16 万次距离计算/帧。

## 4. 为什么「爆炸范围」成了唯一的命中手段

这是本篇最重要的推论。

单位是一个**点**——在几何上，点的面积是 0。所以：

> 若武器也是一个点或一条线，它命中一个点的概率在连续空间中等于 0。
> 要实现「命中」，只有两条路：**要么把目标变成有面积的圆，要么把武器形状放大成有面积的区域。**

既然单位没有面积，就只能走第二条路：把武器形状放大到「一次能罩住一片点」。

于是「命中」和「范围伤害」在实现上**变成了同一件事**——
`radius: 50` 既是命中判据，也是伤害范围，无法分开。

这就是为什么「加一把只有单体伤害的机枪」在现有架构里表达不出来：机枪需要一个小的命中区，而小命中区配点目标 = 永远打不中。

## 5. 附带后果：命中率恒等于 1

因为 `point` 类武器先锁「最近的敌人」再直接结算，**没有「脱靶」这个概念**。

后果：

- 「机动」「走位」「拉扯」在武器层面没有任何收益（只影响 flocking 的接触频率）
- 无法做「小快目标难打中、大船好打中」这种最基本的太空战斗手感
- 无法做「护盾朝向」——因为弹必然从正面来，或者说根本没有「从哪来」的概念

## 6. 小结

| 症状           | 根因                   | 拆法           |
| ------------ | -------------------- | ------------ |
| 只能用爆炸范围命中    | 单位是点（零测度）            | 给 `u.hitR`   |
| 加武器要改 switch | `shape` 是封闭枚举        | 参数表 + 统一扫掠判定 |
| 弹道改了也打不中     | 判定吃 `p0`/`p1` 的概念不存在 | 扫掠线段判定       |
| 护盾只能全向       | 没有受击方向               | 后续做护盾弧（P4）   |
| 性能随单位数平方增长   | 无空间索引                | `Grid`       |

**这三个耦合必须一起拆。** 只加 `hitR` 而不改判定，武器表还是封闭的；只改判定而不加索引，弹道一多就卡死。
