# 武器系统改造

## 文档定位

这一组文档描述**现有武器系统的底层改造**：从「按武器名硬编码三种形状」改成「扫掠圆 + 正交参数表」。

目标不是加更多武器，是**让加武器这件事变成填表**。

对应的大方向见 `../noita-武器系统解剖与RTS适配.md`（可配置化的设计理念）与 `../攻击与防御机制.md`（现有的三种武器与防御规则）。本篇只谈**底层怎么改**。

## 为什么现在改不了

三个耦合，任何一个不拆都做不成配置化：

1. **单位是点，不是有体积的实体。** 命中判定的输入只有 `{x, y}`，所以只能用「武器形状」把点罩进去——爆炸范围因此成了唯一的命中手段。
2. **武器是封闭枚举。** `WEAPONS` 表里 `shape: "point" | "rect" | "circle"` 决定走哪个 `switch` 分支。加一把枪必须改这个分支。
3. **没有空间索引。** `stepWeapons` 每个单位遍历全部单位找目标（O(n²)），爆炸再遍历一遍。加弹道和体积之后会直接爆掉。

## 改造后的样子

一句话：**每发弹 = 一个沿路径移动的圆；命中 = 这个圆在 `p0 → p1` 的扫掠中碰到过单位的圆。**

这一条统一所有武器：

| 武器 | 表达方式 |
|---|---|
| 机枪 | 高速短寿命弹丸，小 `contactR` |
| 轨道炮 | 同上 + `pierce` |
| 激光 | `hitscan`，扫掠线段，`contactR` = 光束半宽 |
| 导弹 | 飞行弹丸 + 追踪力 |
| 鱼雷 | 飞行弹丸 + 不追踪 + 命中后 `blastR` |

**关键的认知**：命中判定只吃「这一帧从哪走到哪」，不吃「为什么这么走」。
所以弹道（直线 / 追踪 / 螺旋 / 被风吹）和命中是**解耦**的——改弹道不会影响命中，这正是配置化的前提。

## 关键决策（先记在这里，细节在各自文档）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 用**圆**做受击体积，不用多边形 / 装甲格 | 200–400 单位规模扛不住；圆够用 |
| D2 | 命中用**扫掠线段**，不用逐帧点测试 | 防隧穿（900 速弹一帧走 15px > 单位尺寸） |
| D3 | 把 `contactR`（命中）和 `blastR`（爆炸）**拆成两个参数** | 现在二合一，导致所有武器被迫用 AoE 命中 |
| D4 | `pierceShield: bool` → `shieldMul: number` | 布尔只能表达穿/不穿；倍率能表达「被吃 70%」 |
| D5 | `range` 不再是独立字段，改为 `speed × lifetime` | 现在射程和弹速无关，是凭空数字；推导后「同射程慢弹更难命中」才成立 |
| D6 | `rRep`（分离半径）与 `hitR`（受击半径）**保持独立，不互相推导** | 前者是**编队密度**（移动层），后者是**战斗几何**（武器层）。让移动层从武器层参数推导 = 让移动层依赖武器层，破坏解耦；而且会把 5 个模板原有的阵型差异（17/30/34/22/32）抹平成同一个常数 |
| D7 | 舰队做**多挂点**，不做更多枪 | Starsector 的配置感来自「一船多炮」，不是「枪的种类多」。挂点只是配置位，**不带射界** |
| D8 | **不做炮塔 / 射界 / 转向** | 大群 RTS 里朝向的战术收益无法被感知；射界只会带来「转身时不能开火」的手感噪声 |
| D9 | 武器表里**不出现随机数** | `spread` 改为确定性的 `fan`；否则 DPM 不可算，差分测试也无法做 |
| D10 | 空间索引**只服务武器系统**，群体层完全不接入 | 群层的查询半径 17~350，最频繁的那档（寻敌 350）网格只值 1.8×，还要付出两段式积分的重构代价；群层该先做小队聚合，那是另一件事（详见 05 第 5.6 节） |

## 明确不做

- 装甲格 / 子系统（引擎、武器、弹药库独立血量）—— 单位数量扛不住
- 真实刚体碰撞 —— 大群 RTS 不需要，且会破坏 flocking 的平滑感
- 弹丸之间的碰撞 —— 同上
