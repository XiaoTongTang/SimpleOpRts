核 心 目 的

整段代码只做一件事：把一条几何陈述，改写成一条代数方程，好让求根公式能用。

|p(t) − c|² = rr² 几何陈述：某一时刻，弹丸到圆心的距离恰好等于 rr
↓　把 p(t) = p0 + t·d、f = p0 − c 代进去，展开点积
A·t² + B·t + C = 0 代数方程：t 的二次多项式
↓　求根公式
t = (−B ± √(B² − 4AC)) / 2A

第一行说得对，但解不出来——t 埋在向量 p(t) 里、又埋在范数里， 而求根公式只认多项式。第三行才是能算的形式。

中间出现的 rr、d、f、a、b、cc 全部只是为了完成这一次改写而引入的中间量。 它们不是新的条件，不是新的约束，也不构成第二个方程。

0 · 这段代码在回答什么

一发半径 r 的弹丸，这一帧从 p0 扫过到 p1。 一个半径 R、圆心 c 的圆（舰船），这一帧不动。

问两件事：

  1. 这一帧有没有撞上？
  2. 如果撞上了，撞上的时刻在帧内的哪个位置？

位置用归一化参数 t ∈ [0,1] 表示——t=0 帧首，t=1 帧末。 这个 t 就是返回值，也是整个函数除「命中/未命中」之外的全部信息量。

为什么不逐帧做「点 vs 圆」测试？
因为会隧穿。dt = 1/60，弹速 900 时一帧走 15px，比单位半径（≈4.5）还大。 逐帧测试会直接从目标身上跳过去。扫掠判定用「线段」代替「点」，天然免疫。

1 · 第一步：闵可夫斯基和

两个圆相交的充要条件是圆心距 ≤ 半径之和：

|P弹 − P目| ≤ R + r

把 r 挪到右边：

|P弹 − P目| ≤ (R + r)

这在几何上叫闵可夫斯基和（Minkowski sum）的一个特例：圆 ⊕ 圆 = 圆，半径相加。

等价表述：把弹丸缩成一个点，把舰船膨胀成半径 R+r 的大圆。 判定结果一模一样。

于是整段代码只需要处理「点 vs 圆」，永远不用处理「圆 vs 圆」。

rr = R + r = 14.00 // 图中那条青色虚线圆
这一行不是「为了省事把两个半径加起来」，是一次严格的等价变换。 它是整段代码的地基——后面所有公式都建立在「弹丸是一个点」这个前提上。 图中那条虚线圈就是它：弹丸的圆心一旦碰到这条线，就是命中。

2 · 第二步：把线段写成方程

p(t) = p0 + t·d t ∈ [0,1] d = p1 − p0 // 这一帧的位移向量 f = p0 − c // 帧首时，弹丸相对圆心的位置
d = (0, 0) f = (0, 0)

只需要这两个向量，后面所有量都能从它们导出。图里的紫色箭头是 f，灰色箭头是 d。

3 · 第三步：写出相交条件

「点在 t 时刻压在大圆边界上」：

|p(t) − c|² = rr² |f + t·d|² = rr² // 同一个式子的另一种写法，不是第二个条件
注意：这不是两条方程，是同一条。
p(t) − c 和 f + t·d 是同一个向量，只是换了个名字： (p0 + t·d) − c = (p0 − c) + t·d，三项恒等，没有近似。
写第二遍的唯一目的，是把 t 从范数里挖出来，变成能套求根公式的多项式。 类比：x + x + 1 = 5 和 2x = 4 是同一条方程，不是两条。
代码里最终也只有一条：a·t² + b·t + cc = 0。前两行都只是它的「人话版本」。

展开点积：

(f + t·d)·(f + t·d) = rr² f·f + 2t(f·d) + t²(d·d) = rr²

移项，得到标准的 a·t² + b·t + cc = 0：

系数代码表达式含义
adx*dx + dy*dy|d|²这一帧走了多远的平方。必须 > 0
b2*(fx*dx + fy*dy)2(f·d)位移方向与「弹丸→圆心」方向的点积 ×2
ccfx*fx + fy*fy - rr*rr|f|² − rr²帧首距离平方减去半径平方
a = 0 b = 0 cc = 0
命名陷阱：代码里叫 cc 不叫 c，因为 c 已经被「目标圆心」占用了。 但它不是标准二次方程里的 c，它是常数项。 读的时候别按 ABC 套公式——记住 cc 的单位是「长度²」就对了。

4 · 第四步：判别式

disc = b² − 4·a·cc = 0
disc几何含义处理
< 0直线与圆无交点return -1
= 0相切（擦边），算命中一个根
> 0两个交点：进入 + 离开取先发生的那个

注意这一步的严谨性：解出来的是无限长直线与圆的交点，不是线段。 但线段是直线的子集，所以「直线无交点」⟹「线段无交点」—— 这个提前返回是安全的、不是猜的。

5 · 第五步：取左根 = 进入时刻

t = (−b ± √disc) / (2a) // 两个根 = 进入 / 离开

因为 a = |d|² > 0（二次项系数为正，抛物线开口向上，对应「速度不变」所以是个匀速运动），所以：

左根 (−b − √disc)/(2a) < 右根 (−b + √disc)/(2a)

左边先发生，是进入时刻。我们要的是「第一次撞上」，所以取左根。

6 · 四个提前返回分支

这里是这段代码真正的功夫。它们不是「防御性编程」的装饰，每一条都对应一个会算错的真实几何构型。 按下面任意一个预设按钮，对应的分支会亮起来。

6.1 起点已重叠 → return 0

帧首已重叠

if (fx*fx + fy*fy <= rr*rr) return 0;

这一行不是优化，是正确性所必需的。

反证：如果起点在圆内，则 cc = |f|² − rr² < 0。那么

两根之积 = cc / a < 0

两根异号。左根是负数，会被最后一行 t >= 0 判掉，函数返回 -1 —— 漏判一次明明已经贴脸的命中。

现在点「帧首已重叠」预设，看左边仪表盘：t₀ 会显示一个负数 （约 −0.2204），但判定结果仍然是 0。这就是证据。

语义上：帧首就已经重叠，返回 t = 0 表示「这一刻就算命中」。

为什么用 <= 而不是 <？ 起点恰好压在边界上时 cc = 0，两根是 0 和 −b/a。 若 b > 0，左根 = −b/a < 0，一样会被判掉。 所以必须把「贴边」也算进「已重叠」。这个等号是刻意的。

6.2 弹丸没动 → return -1

弹丸静止

if (a < 1e-9) return -1;

a = |d|²。若 a ≈ 0，两个后果：

  1. 后面除以 2a 会除零或精度崩塌；
  2. 语义上，一个完全静止的弹丸不可能撞上任何东西——而「起点就重叠」那种情况 6.1 已经截走了。

所以这里返回 -1 是正确的，不是没考虑到的退化情形。

6.3 无交点 → return -1

无交点

if (disc < 0) return -1;

见第 4 节。图中表现为：线段整条都在青色膨胀圆的外面。

6.4 线段范围外 → 最后一行裁剪

交点在后方

t < 0：交点在 p0 的后方——弹已经飞过目标，正在远离。不算命中。

这一帧还走不到

t > 1：交点在 p1 的前方——这一帧还走不到，下一帧再算。

点这个预设，t₀ ≈ 1.6400，你能直接看到为什么 t <= 1 这个裁剪不能省。

命中

return (t >= 0 && t <= 1) ? t : -1;

这就是「线段」与「直线」的分界，也是这个函数正确的关键。 上界 t <= 1 和下界 t >= 0 各裁掉一种构型，剩下的才是真命中。

7 · 手算一遍

取 p0 = (0,0)，p1 = (100,0)，r = 2，c = (50,10)，R = 10，于是 rr = 12。

d = (100, 0) f = (-50, -10) a = 100² = 10000 b = 2·(-50·100 + (-10)·0) = -10000 cc = (2500 + 100) − 144 = 2456 disc = 10000² − 4·10000·2456 = 1,760,000 √disc ≈ 1326.65 t = (10000 − 1326.65) / 20000 = 0.4337

命中点 = (43.37, 0)。

反验：到圆心 (50,10) 的距离 = √(6.63² + 10²) = √143.97 ≈ 12.00 = rr ✅

擦边特例：把 R 改成 8（rr = 10），则 cc = 2500， disc = 1e8 − 1e8 = 0，t = 0.5，命中点 (50,0)， 到圆心距离正好 10。相切，代码不需要特殊处理也能算对。 点顶部的「相切」预设可以看到这个状态。

8 · t 不只是布尔值

返回一个数而不是 true，是为了三件事。

① 爆炸要炸在命中处，不是帧末处

const hx = p0.x + t * (p1.x - p0.x); const hy = p0.y + t * (p1.y - p0.y);

否则高速弹的爆炸会往前窜一截，视觉和数值都对不上。图中那个绿色圆点就是 h。

② 穿透排序

一发贯穿弹这一帧可能同时命中 3 个目标。收集所有 t、升序排、取前 pierce+1 个—— 这就是「先打中谁」。

hits.sort((A, B) => A.t - B.t);

③ 确定性

t 是连续的，排序稳定。但两个目标正面对齐时 t 可能完全相同， 要加 tiebreak（按单位 id），否则结算顺序会随数组顺序抖动。 这正是 04-改造步骤.md 里那个「网格导致的蝴蝶效应」的来源。

9 · 已知局限

诚实列出，不建议现在解决。

  1. 假设帧内是直线。追踪弹在这一帧内是转弯的，严格应该用弧线扫掠。 dt = 1/60 且转向速率有限时，直线段近似足够；要更准就把一帧拆成 N 个子步，通常 N = 2 就够。
  2. 只处理圆。驱逐舰这种长条，用单圆会「头尾判小、腰判大」。 解法是多圆胶囊——沿舰体中轴排 2–3 个圆，每个独立判定。不是 OBB，后者数学多一维，收益有限。
  3. 目标视为帧内静止。目标速度约 96 px/s，一帧 1.6px，最多带来 1.6px 误差， 远小于 hitR ≈ 4.5，可以接受。
  4. 它只回答「我和这一个目标」。谁先撞、撞几个，是调用方的事。

10 · 为什么这 20 行能统一所有武器

关键在于：它只吃 p0 → p1，不吃「为什么这么走」。

武器怎么调用它
机枪p0 到 p1 是这一帧的位移，速度 × 寿命给出总长度
激光同上，但整条线在一帧内走完（hitscan）
轨道炮同上 + pierce = 3
导弹先积分追踪力得到 p1，再调用
弹跳弹先把速度关于墙反射，得到 p1，再调用
弹道怎么配，这个函数一行都不用改。 这就是「配置化」的地基——不是把字段变多，是让判定和弹道互不认识。

附 · 完整代码

/** * 扫掠圆判定：半径 r 的弹丸从 p0 走到 p1，是否撞上半径 R、圆心 c 的圆。 * @returns {number} 命中时刻 t ∈ [0,1]；未命中返回 -1 */ function sweptHit(p0, p1, r, c, R) { const dx = p1.x - p0.x, dy = p1.y - p0.y; const fx = p0.x - c.x, fy = p0.y - c.y; const rr = R + r; // 闵可夫斯基和：圆 ⊕ 圆 = 圆 if (fx*fx + fy*fy <= rr*rr) return 0; // 帧首已重叠（含贴边） const a = dx*dx + dy*dy; // |d|² if (a < 1e-9) return -1; // 静止弹丸撞不到任何东西 const b = 2*(fx*dx + fy*dy); // 2(f·d) const cc = fx*fx + fy*fy - rr*rr; // |f|² − rr² const disc = b*b - 4*a*cc; if (disc < 0) return -1; // 无限长直线都无交点，线段更不会有 const t = (-b - Math.sqrt(disc)) / (2*a); // 取左根 = 进入时刻 return (t >= 0 && t <= 1) ? t : -1; // 裁到线段范围内 }
