# 舰船朝向平滑 · 1€ 滤波器技术设计

> 目标：**只在渲染层**给舰船朝向加一层「速度自适应」的平滑（1€ 滤波器），
> 抹掉鸟群力场带来的高频抖动，但保留大角度转向的灵敏响应。
>
> 范围：`src/render/`。**不动 core、不动模拟、不动快照、不动存档。**
>
> 状态：**已实现**（2026-11-08）

## 0. 一句话结论

在 `render-pixi.js` 的 `drawUnits()` 里，把「直接拿 `atan2(vy,vx)` 当朝向」换成
「把 `atan2(vy,vx)` 喂给每艘船一个 `OneEuroAngle` 滤波器」：

- 角速度小（贴着编队、悬停、互相挤压）→ 截止频率压到 ~1.5 Hz，抖动被抹平；
- 角速度大（真的在掉头 / 信标带着急转）→ 截止频率被 `beta × |ω|` 顶高，几乎不增延迟。

滤波器状态按**单位对象**存（`WeakMap`），不按精灵下标存 —— 顺带修掉现在精灵池复用会串朝向的隐患。

## 1. 现状与问题

### 1.1 现在的朝向是怎么来的

`src/render/render-pixi.js` · `drawUnits()`：

```js
// 航向：静止时保持上一帧朝向，避免抖
const sp = Math.hypot(u.vx, u.vy);
if (sp > 4) s._ang = Math.atan2(u.vy, u.vx);
s.rotation = s._ang + Math.PI / 2;     // 素材船头朝上
```

只有一个「速度 < 4 px/s 就锁角」的硬死区，没有任何时间维度的滤波。

### 1.2 抖动从哪来

`src/core/sim/group-layer.js` 的软化 Couzin 力场每帧合成
分离 / 对齐 / 凝聚 / 威胁 / 寻敌 / 命令 / 边界力，再积分速度：

| 量 | 值 | 影响 |
|---|---|---|
| `SPD` | 96 px/s | 巡航速度量级 |
| `MAX_ACCEL` | 430 px/s² | 单帧速度向量最多改变 ~7 px/s（60 fps） |
| `drag` | 0.30 | 阻尼小，扰动衰减慢 |
| `stallSpeed / stallAccel` | 60 / 100 | **低速时沿当前朝向补推力，等于把方向误差放大** |

朝向取的是**速度方向**，于是：

1. **速度越小声噪比越差**：`v = 96` 时 5° 的力扰动只改变一点方向；`v = 10` 时同样大小的横向扰动就是几十度。低速编队内挤压、贴边、绕圈时角度噪声最大。
2. **邻居进出感知圈是突变的**：某艘友舰从 `rRep` 里外穿过，分离力的方向在一两帧内翻转，速度方向随之拐一下 —— 这就是帧级的「抽一下」。
3. **对齐项只取「幅值 > 1」的邻居平均速度**（`group-layer.js` L176），邻居集合变化时平均速度的方向也会跳变。
4. 死区只在 `sp ≤ 4` 时生效；**抖动最明显的 5–30 px/s 区间完全没有保护**。

### 1.3 这个抖动是纯视觉问题

- 武器命中判定用位置 + 速度（扫掠圆），**不看朝向**；朝向不参与任何战斗计算；
- `snapshot()` 不含朝向；
- 所以朝向只是「画给玩家看的」，在这里做时间滤波不会改变任何游戏结果、不会破坏确定性。

### 1.4 顺带发现的一个小 bug

`_ang` 存在**精灵**上，而精灵池是按 `n++` 顺序复用的（`drawUnits()` 里 `const s = this.sprites[n++]`）。
当有船死亡、后面的船顶上这个精灵下标、而新船速度又低于 4 px/s（锁角状态）时，它会先顶着一艘死船的朝向站一两帧才被纠正。
按单位对象存滤波器状态可以从根上避免。

## 2. 目标 / 非目标

### 目标

1. 消除编队行进、低速挤压、贴边绕行时的朝向高频抖动（目标：抖动的二阶差分标准差下降 ≥ 70%）。
2. 大角度转向（命令信标急转、掉头）**肉眼几乎感觉不到额外延迟**（目标：≤ 0.1 s 的额外滞后）。
3. 实现只在渲染层，零模拟改动、零存档改动、零快照字段。
4. 参数集中、可调、可在控制台现场试。
5. 首次出现 / 暂停 / 掉帧 / 跨 ±π 都能正确处理。

### 非目标

- **不**改鸟群算法本身。如果编队本身在「转圈 / 互相推挤」，那是行为参数（`wSep`、`rRep`、`omega`…）的问题，滤波器只负责别把这份抖动放大到画面上。
- **不**平滑位置。位置抖动是另一类问题（会表现为船体滑移），这里只动旋转。
- **不**平滑速度、不**回写** `unit.vx/vy`。
- **不**限制转向速率。战场上有大量大幅度掉头，任何「每秒最多转多少度」的限速都会拖慢真实转向；这里只滤「小的扰动」。
- 不做镜头相关的处理（缩放/平移与朝向无关）。
- 不引入第三方库（1€ 就 40 行）。

## 3. 为什么是 1€ 滤波器

| 方案 | 稳态平滑 | 转向延迟 | 参数 | 结论 |
|---|---|---|---|---|
| 现状：速度死区 | 无（> 4 px/s 完全不滤） | 0 | 1 个阈值 | 抖动照旧 |
| 固定指数平滑（EMA） | 好（α 小） | **大且固定** | 1 个 α | 要么抖、要么肉，二选一 |
| 滑动平均（N 帧） | 好 | 大（≈N/2 帧），且吃帧率 | N | 同上，还依赖帧率 |
| 临界阻尼弹簧 / SmoothDamp | 好 | 中等且固定 | 平滑时间 | 转向手感「黏」，且要处理过冲/回弹 |
| **1€ 滤波器** | **好（截止频率低）** | **小（角速度大时自动放开）** | **fc_min + β（+ 固定的 fc_d）** | ✅ |

1€ 的核心是**截止频率随信号变化速度自适应**：

```
cutoff = fc_min + β × |滤波后的角速度|
```

- 静止 / 微抖：`|ω| ≈ 0` → `cutoff = minCutoff`（低）→ 强平滑。
- 真转向：`|ω|` 大 → `cutoff` 抬高 → 平滑变弱、跟上目标。
- 关键细节：`|ω|` 本身先被一个低通（`fc_d`，参考实现固定 1 Hz）滤过，所以**每帧来回摆的噪声不会被误判成「真转向」**，不会自己把截止频率顶上去。

这正是「滤掉微小抖动、保留大幅转向」的直接实现，而且不需要我们手动做「抖动 vs 转向」的状态机判定。

## 4. 算法

### 4.1 标准 1€（一维信号）

```
τ(cutoff) = 1 / (2π · cutoff)
α(cutoff, dt) = dt / (dt + τ)
```

每帧：

```
dx        = (x - xPrev) / dt
dxHat     = dxHat + α(fc_d, dt) · (dx - dxHat)      // 角速度的低通
cutoff    = fc_min + β · |dxHat|
xHat      = xHat + α(cutoff, dt) · (x - xHat)       // 输出
```

`xHat` 是滤波后的信号；`dxHat` 是滤波后的导数。**三个参数：`fc_min`、`β`、`fc_d`。**
参考实现把 `fc_d` 默认成 1 Hz，所以日常只看到前两个 —— 本设计也照此处理（见 §5.1.1）。

### 4.2 角度适配（唯一需要改的数学）

角度是**环形量**，不能直接把 `-π` 和 `+π` 当两个相距 2π 的数去滤，否则每次跨越接缝都会整整转一圈。做法：

1. 所有差值都取**最短弧**：

```
wrapPi(a) = ((a + π) mod 2π + 2π) mod 2π - π     // → (-π, π]
```

2. 滤波器内部只存**已包裹的**角度 `xHat`；
3. 每帧的增量 `d = wrapPi(target − xHat)`，用 `d` 去做导数和插值：

```
d      = wrapPi(target − xHat)
raw    = d / dt
dxHat += α(fc_d, dt) · (raw − dxHat)
cutoff = fc_min + β · |dxHat|
xHat   = wrapPi(xHat + α(cutoff, dt) · d)
```

这样 179° → −179° 会被理解成「转 2°」，而不是「转 358°」；输出始终落在 `(-π, π]`，不会随时间长出很大的浮点数。

> 超出 ±π 的单帧转动（60 fps 下 > 180°/帧 ≈ 30 圈/秒）在视觉上本来就会频闪，按最短弧处理即可，不需要额外分支。

### 4.3 低速锁定

速度幅值低于阈值时，「朝向」本身没有意义（速度向量就是噪声）。沿用现有语义，但把阈值从 4 px/s 提到 **6–8 px/s** 并加一点迟滞：

- `sp < LOCK_IN (6 px/s)`：**不喂新测量**，输出停在最后的角度；
- `sp > LOCK_OUT (10 px/s)`：恢复喂测量；
- 中间区间保持上一帧的锁定状态。

滤波器本身不需要 reset —— 锁定时不调用 `filter()` 就行，恢复时用同一份状态继续（一次平滑过渡，比瞬间对齐更自然）。

### 4.4 参考实现（约 60 行）

`src/render/angle-filter.js`（新文件，纯函数，可被 node 直接测试）：

```js
/**
 * 对外只有两个可调参数（和标准 1€ 的 fc_min / β 一一对应）。
 * fc_d（导数低通截止频率）是原论文的第三个参数，参考实现默认 1 Hz，
 * 这里作为常量固定下来，不参与日常调参 —— 见 §5.1 的说明。
 */
export const ANGLE_FILTER = {
  minCutoff: 0.005,   // Hz  · fc_min：角速度≈0 时的截止频率
  beta: 0.001         // s/rad · β：每 1 rad/s 的角速度把截止频率抬高多少 Hz
};

const D_CUTOFF = 1.0;   // Hz · fc_d：角速度估计自身的低通（论文默认 1 Hz）

const TAU = Math.PI * 2;

export function wrapPi(a) {
  a = (a + Math.PI) % TAU;
  if (a < 0) a += TAU;
  return a - Math.PI;
}

function alpha(cutoff, dt) {
  const tau = 1 / (TAU * cutoff);
  return dt / (dt + tau);
}

export class OneEuroAngle {
  constructor(opts = ANGLE_FILTER) {
    this.o = opts;
    this.x = 0;      // 滤波后的角度
    this.dx = 0;     // 滤波后的角速度（rad/s）
    this.init = false;
  }

  reset(angle) {
    this.x = wrapPi(angle);
    this.dx = 0;
    this.init = true;
  }

  /** @param {number} target 目标角度（rad，任意范围） @param {number} dt 秒 */
  filter(target, dt) {
    if (!this.init) { this.reset(target); return this.x; }
    if (!(dt > 0)) return this.x;                 // 暂停 / 同一帧，不动
    const h = Math.min(dt, 0.1);                  // 掉帧保护

    const d = wrapPi(target - this.x);
    const raw = d / h;
    this.dx += alpha(this.o.dCutoff ?? D_CUTOFF, h) * (raw - this.dx);

    const cutoff = this.o.minCutoff + this.o.beta * Math.abs(this.dx);
    this.x = wrapPi(this.x + alpha(cutoff, h) * d);
    return this.x;
  }
}
```

> 故意**不设转向速率上限**：真实战场大量出现大幅度掉头，限速会把「真掉头」也拖慢。
> 这一层的职责只有「滤掉小的扰动」，不是「让船转得慢」。
> 1€ 的 `beta` 项本身就能区分二者：小幅高频 → 角速度估计被 `fc_d` 抹平 → 强平滑；
> 大幅单向 → 角速度估计真的很高 → 放开。掉头的响应速度见 §5.3 实测。

## 5. 参数

### 5.1 参数：两个可调 + 一个固定

| 参数          | 默认            | 对应标准 1€ | 含义          | 调大         | 调小        |
| ----------- | ------------- | ------- | ----------- | ---------- | --------- |
| `minCutoff` | **1.5 Hz**    | `fc_min` | 静止时的截止频率    | 更跟手，但抖     | 更稳，但转向起手慢 |
| `beta`      | **1.0 s/rad** | `β`     | 角速度对截止频率的放大 | 大转向更灵敏     | 大转向更「肉」   |

固定常量（不作为调参项）：

| 常量         | 值        | 对应标准 1€ | 说明                                    |
| ---------- | -------- | ------- | ------------------------------------- |
| `D_CUTOFF` | **1.0 Hz** | `fc_d`  | 角速度估计自身的低通；论文参考实现的默认值，见 §5.1.1 |

> 日常只有 `minCutoff` 和 `beta` 两个旋钮 —— 和大多数「标准 1€ 只有两个参数」的说法一致。
> 没有「最大转向速率」：大角度掉头必须能一帧见效，见 §5.3。

#### 5.1.1 为什么代码里还有第三个量 `fc_d`

**因为标准 1€ 本来就是三个参数。** 原论文（Casiez / Roussel / Vogel, CHI 2012）的算法是：

```
dx      = 低通( (x - xPrev)/dt , fc_d )     ← 第三个截止频率，用来估角速度
cutoff  = fc_min + β·|dx|
xHat    = 低通( x , cutoff )
```

官方参考实现 `OneEuroFilter(freq, mincutoff, beta, dcutoff = 1.0)` 把 `fc_d` 直接默认成 1 Hz，
很多教程和库只暴露前两个旋钮，于是它在文档里「消失」了。本设计沿用这个习惯：
**`fc_d = 1 Hz` 固定，不参与日常调参。**

它在我们这里值得单独写清楚，是因为**角度信号的导数噪声占比很大**（像素坐标的 1€ 通常不在意这一点）。
用默认 `fc_min=1.5 / β=1.0` 实测（60 fps）：

| `fc_d` | 抖动保留 | 90° 阶跃（63%） | 6 rad/s 跟踪误差 |
| --- | --- | --- | --- |
| ∞（不滤导数） | 15.8 % | 17 ms | 4.5° |
| 5 Hz | 9.1 % | 17 ms | 4.5° |
| 2 Hz | 8.1 % | 17 ms | 4.5° |
| **1 Hz（默认）** | **7.7 %** | **33 ms** | **4.5°** |
| 0.5 Hz | 7.9 % | 33 ms | 4.5° |

读法：`fc_d` 越低，越不把「每帧来回摆」当成真转向，抖动压得越狠；代价只是**阶跃**的上升时间变长
（17 → 33 ms，仍然远小于 0.1 s），对**持续**转向的跟踪误差完全没影响（都是 4.5°）。
所以 1 Hz 是「抖动最省、转向几乎不损失」的那个点；只有实机发现「单帧方向突变被跟得太快」时，
才需要把它降到 0.5–0.7 Hz。

### 5.2 数值感受（60 fps）

| 场景 | `\|ω\|` | 有效 cutoff | 每帧 α | 时间常数 |
|---|---|---|---|---|
| 悬停 / 微抖 | ~0 | 1.5 Hz | 0.14 | ~106 ms |
| 编队缓行 | 0.5 rad/s | 2.0 Hz | 0.17 | ~80 ms |
| 常规转向 | 3 rad/s | 4.5 Hz | 0.32 | ~35 ms |
| 急转 / 掉头 | 6 rad/s | 7.5 Hz | 0.44 | ~21 ms |

即：**抖动被 ~100 ms 时间常数压住；真实匀速急转（6 rad/s）的跟踪误差只有 ~5°，大约 1 帧的方向差。**

### 5.3 大幅掉头的响应（不限速）

因为不做转向限速，一次性的大角度阶跃会**几乎立刻**被跟上 —— 这正是要的效果：

| 输入 | 首帧转过的角度 | 到达 63% | 到达 90% |
|---|---|---|---|
| 90° 阶跃 | **47°** | 33 ms | 50 ms |
| 180° 掉头 | **120°** | 首帧已过半 | ~50 ms |

原因：`d` 一下子变得很大 → 角速度估计瞬间拉高 → `cutoff` 被 `beta` 顶到十几 Hz → `α` 接近 0.7。
所以「真掉头」在画面上是跟手的一两帧，而不是被滤镜拖成慢动作；
被滤掉的只有**双向、小幅、高频**的扰动（§附录取样里保留了 7.7%）。

代价要说清楚：如果某一帧目标角度因为邻居突然进出感知圈而**单帧翻转 180°**，滤镜也会把它当「真掉头」快速跟过去。
这是有意的取舍 —— 我们宁可跟手，也不要把真实的大幅转向拖慢。

### 5.4 调参对照表

| 症状 | 调整 |
|---|---|
| 还有细碎抖动 | `minCutoff` 1.5 → 1.0 |
| 转向起手发黏 | `beta` 1.0 → 1.4 |
| 大转向时「过头 / 抖一下」 | `beta` 调小 |
| 单帧方向突变被跟得太快（罕见） | 改固定常量 `D_CUTOFF` 1.0 → 0.7（不是常规旋钮） |
| 某类阵型（大间距、散射）特别抖 | 先查 `wSep/rRep`，不要只怪滤波器 |

调参方式：控制台 `__RENDERER.angleOpts.beta = 1.4`（实现时暴露这个对象即可，见 §6.4），
或 URL `?angle=0` 直接关掉滤镜做 A/B 对照。

### 6.2 改动文件

`src/render/render-pixi.js`：

```js
import { OneEuroAngle, ANGLE_FILTER } from "./angle-filter.js";

const ANGLE_LOCK_IN  = 6;    // px/s 以下不喂测量
const ANGLE_LOCK_OUT = 10;   // px/s 以上恢复

class PixiRenderer extends WorldRenderer {
  constructor() {
    super();
    ...
    this.angleFilters = new WeakMap();   // unit 对象 → OneEuroAngle
    this.lastTime = 0;
    this.angleOpts = { ...ANGLE_FILTER }; // 便于控制台调参
  }

  draw(view) {
    let dt = view.time - this.lastTime;
    if (!(dt > 0) || dt > 0.5) dt = 0;   // 暂停 / 重开导致的时间回跳
    this.lastTime = view.time;
    ...
    this.drawUnits(view, dt);
  }

  drawUnits(view, dt) {
    ...
    const sp2 = u.vx * u.vx + u.vy * u.vy;
    let f = this.angleFilters.get(u);
    if (!f) {
      f = new OneEuroAngle(this.angleOpts);
      f.reset(Math.atan2(u.vy, u.vx));
      this.angleFilters.set(u, f);
    }

    // 带迟滞的低速锁：锁定时不喂新测量，朝向保持
    if (sp2 > (f.locked ? ANGLE_LOCK_OUT : ANGLE_LOCK_IN) ** 2) {
      f.locked = false;
      f.filter(Math.atan2(u.vy, u.vx), dt);
    } else if (sp2 < ANGLE_LOCK_IN ** 2) {
      f.locked = true;
    }

    s.rotation = f.x + Math.PI / 2;      // 素材船头朝上
    ...
  }
}
```

要点：

- **状态按 `unit` 对象存**（`WeakMap`），不存精灵：船死了对象被回收，精灵复用不会串朝向（同时修掉 §1.4）。
- `dt` 用 `view.time`（模拟时间）的差分，天然满足「暂停就不更新」；但要注意 `reset` 会把时间归零，所以 `dt ≤ 0` 或 `> 0.5` 一律按 0 处理。
- `atan2` 每帧每船一次（原来就有），额外开销只有两次 `exp`（`alpha()` 里的 τ）。
- **删掉** `s._ang` 字段（不再需要）。
- 精灵是否换贴图、大小、tint、旋转偏移（+π/2）都不变。

### 6.3 需要同时确认的调用方

- `src/main.js`：`renderer.draw(view)` 已经在主循环里每帧调用，**不需要改**。
- `src/render/renderer.js`：`WorldRenderer` 的接口文档里补一句「朝向可在实现层做时间滤波，属于表现细节」。
- `src/core/*`：**零改动**。

### 6.4 调试开关（可选但建议）

```js
window.__RENDERER.angleOpts        // 直接改参数，下一帧生效
window.__ANGLE_OFF = true          // 临时关闭，做 A/B 录屏
```

再加一个 URL 参数 `?angle=off` 更稳定（不依赖控制台手速）。

## 7. 时序 / 生命周期

| 事件 | 行为 |
|---|---|
| 单位首次出现 | `reset(atan2(vy,vx))`，第一帧不发散、不从 0 扫过去 |
| 单位死亡 / 被移除 | `WeakMap` 条目随对象回收，无需清理 |
| 暂停 | `view.time` 不变 → `dt = 0` → `filter()` 直接返回当前值，画面绝对静止 |
| 继续 | `dt` 恢复正常，状态连续，不会「补帧」 |
| 重开（reset） | 时间回 0、单位对象全新 → `dt` 被夹成 0、`WeakMap` 自然重建 |
| 掉帧 / 切后台 | `dt` 夹到 0.1 s；α 趋近 1，直接贴住目标，不会过冲 |
| 高刷屏（144 Hz / 60 Hz 模拟） | 没跑到模拟帧的显示帧 `dt = 0`，朝向保持不变（速度也没变），不会抖 |
| 跨 ±π | 最短弧，永不绕远路 |

## 8. 性能

- 每船每帧：1× `atan2`（已有）+ 1× `exp`（`alpha`）+ 几次乘加。
- 500 艘 ≈ 0.05–0.1 ms/帧，相对于 Pixi 的批处理可以忽略。
- `WeakMap` 的 `get/set` 只在首次创建和每帧读取，V8 下是哈希查找；若嫌慢，可在单位上挂 `u.__af`（渲染层私有字段，不算游戏状态）——但**不推荐**，污染 core 对象。
- `alpha(D_CUTOFF, dt)` 每帧对所有船相同，可提到 `drawUnits` 外层算一次，只留 `alpha(cutoff, dt)` 每船算。

## 9. 风险与边界

1. **参数调错 → 转向发肉**：`minCutoff` 太低 + `beta` 太小。默认值就是按「1 帧多延迟」标定的，改之前先录屏对比。
2. **滤波器不解决行为层抖动**：如果某套阵型本身在互相推挤绕圈，画面上会变成「一条平滑的乱扭曲线」——那要去调 `wSep/rRep/omega`，不是滤镜的锅。
3. **`reset` 时间回跳**：必须处理 `dt < 0`，否则会出现一次巨大的 `raw` 把 `dxHat` 顶飞（已包含在 §6.2）。
4. **首次出现的船**：初始化成当前速度方向，不应从 0 开始（否则满场船会「扫」一下）。
5. **极近失速 + 推力抖动**：`stallAccel` 会让速度在 ±60 px/s 附近来回，朝向可能缓慢「画圈」。这是模拟层现象，滤镜只能让它变慢变圆，不能消除；如果玩家反馈「原地转圈」，另开行为层 issue。
6. **视觉一致性**：平滑只作用于旋转，船体位置仍是未滤波的 —— 大转向时会出现「船头先转、船身继续滑」的一点点侧滑感，这恰好是太空船该有的观感。觉得侧滑太重就调大 `beta`（跟得更紧），**不要**去加转向限速。

## 12. 备选与后续

- **给位置也做同样的滤波**：能治「船体抖动」，但会让单位视觉位置与命中位置不一致（命中用未滤波坐标），不建议。
- **速度/角速度外推**：用 `omega` 做一帧预测可以再降 ~半帧延迟，收益小、复杂度高，暂不做。
- **按舰型分参数**：小艇可以更灵敏、堡垒级更迟钝，等舰种差异明显了再说。
- **事件驱动的「瞬转」**：比如掉头时允许 `beta` 短时放大，暂不需要，1€ 已经够。
- **参考**：Casiez, Roussel, Vogel. *1€ Filter: A Simple Speed-based Low-pass Filter for Noisy Input in Interactive Systems*. CHI 2012.

## 附：为什么不是「把速度向量本身滤一下」

看起来更省事：`vHat = lerp(vHat, v, α)`，然后用 `atan2(vHat)`。
但速度幅值也一起被滤了，低速时会把方向也带慢；而且 `vHat` 和真实速度的差会让人误以为是移动逻辑在漂。
只滤角度：语义最窄、改动面最小、对未来「位置/速度显示」零副作用。

## 附录：默认参数实测

用裸算法（不含引擎、不含转向限速）在 60 fps 下跑了一遍 §5.1 的默认值
（`fc_min = 1.5 Hz, β = 1.0 s/rad, fc_d = 1.0 Hz`；日常只需要调前两个）：

| 用例 | 结果 |
|---|---|
| 30 Hz 噪声 ±0.03 rad（±1.7°） | 输出峰峰 **0.0046 rad**，保留输入的 **7.7%** |
| 90° 阶跃 | 首帧 **47°**；63% = **33 ms**，90% = **50 ms**，过冲 **0.00%** |

| 179° → −179°（跨 ±π） | 实际只转 **1.8°** |

实机接入后若手感不同，优先动 `beta`（灵敏度）和 `minCutoff`（平滑度），见 §5.4。

### 13.2 接入后的行为

- 每艘船的滤波器状态在 `WeakMap<unit, OneEuroAngle>` 里，按**单位对象**索引：
  船死了随对象一起回收，精灵池复用不会串朝向。
- 时间步 `dt` 取 `view.time` 的差分（模拟时间）：暂停时 `dt = 0` → 朝向绝对静止；
  `reset` 后时间回跳（`dt < 0`）或掉帧（`dt > 0.5`）都按 0 处理。
- 低速锁定：`sp < 6 px/s` 不喂新测量、停在最后朝向；`sp > 10 px/s` 自动恢复（迟滞）。
- `?angle=off` 时直接画原始 `atan2`，用于肉眼/录屏对比。
