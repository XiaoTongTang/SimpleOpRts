# 群体行为与小队行为：算法选型手册

**版本** v1.0
**定位** 一份独立、自足的算法目录。不依赖任何具体设计文档，可按需取用、逐项实现。
**适用** 需要"单位自主成群 + 小队自主决策"的实时策略游戏（或任何多智能体实时系统）。

---

## 0. 如何使用本文

本文按**三层**组织，每层只回答一个问题：

| 层 | 代号 | 回答的问题 | 算法 |
|---|---|---|---|
| **支撑层** | S | 谁和谁算"邻居"？空间怎么切？ | 空间哈希、k-NN、DBSCAN、Voronoi、泊松盘、Delaunay、流场 |
| **群体层** | A | 单位怎么**一起动**？ | Boids（力内核）、拓扑交互、Couzin 区语义、ORCA |
| **小队层** | B | 一群人怎么**一起决定**？ | 阈值响应、Utility AI、包容架构、Quorum、拍卖 |

**选型铁律**：每层只选 1~2 个。**能不选就不选。**
每增加一个算法，你都要支付一笔"可读性税"——玩家看不懂的自主行为，等于 bug。

## 1. 五条总原则

| # | 原则 | 反面 |
|---|---|---|
| 1 | **复杂度沉到局部规则里，不要浮到系统层** | 用一个庞大的"任务/契约/状态机"系统去描述群体行为 |
| 2 | **局部交互 + 全局秩序**，不要全局优化器 | 每帧跑一次 PSO 决定所有人该去哪 |
| 3 | **半径分治**：不同规则用不同感知范围 | 分离/对齐/凝聚全用同一个半径 → 互相打架 |
| 4 | **一切离散切换都要滞回** | 目标/角色/姿态每帧翻转 → 数值抽搐、手感电子化 |
| 5 | **可解释性优先于最优性** | 选出理论最优但玩家看不懂的目标 |

## 2. 支撑层（Spatial & Structure）

### S1 均匀网格空间哈希（Uniform Grid）

| 项 | 内容 |
|---|---|
| 原理 | 把空间切成 `2×感知半径` 的格子，每个单位按格索引；查询邻域只看 3×3 格 |
| 用途 | **所有**邻域查询的底层加速（Boids、k-NN、DBSCAN、Quorum 共用一份） |
| 复杂度 | 建表 O(n)，查询 O(1) 平均 |
| 坑 | 格子边长必须 **≥ 最大感知半径**，否则要查 5×5 格；单位高速移动时需按速度扩展查询范围 |

### S2 k-近邻（k-NN）

| 项 | 内容 |
|---|---|
| 原理 | 取最近的 k 个邻居，而非"半径内所有邻居" |
| 用途 | Boids 的邻域定义（见 A2）、"谁该支援谁"、局部密度估计 |
| 复杂度 | O(n·k)，网格加速后接近 O(n) |
| 坑 | k 需 **固定**（通常 6~7）。k 太小队形散，太大反应迟钝 |

### S3 DBSCAN

| 项 | 内容 |
|---|---|
| 原理 | 密度可达：`eps` 邻域内点数 ≥ `minPts` 为核心点，核心点连通成簇，其余为噪声 |
| 用途 | **把连续的运动状态提取成可命名的离散结构**：己方小队、敌方兵力团、障碍物团块 |
| 复杂度 | O(n) 网格加速；O(n log n) 用 R 树 |
| 关键价值 | `minPts` 是**唯一**能阻止"一条长蛇被算成一个小队"的机制（单链接聚类会 chaining） |
| 坑 | **无状态**——每次从零算，label 编号无意义。必须做跨帧匹配与软隶属，否则小队数每帧抖动（见 §8 陷阱 1） |
| 变密度 | 固定 eps 会漏掉小簇。方案：先固定 eps 跑一次，对 `size < minPts` 的簇用 `1.5×eps` 再聚一次。比 HDBSCAN 好调、可预测 |

### S4 Voronoi / 加权 Voronoi

| 项 | 内容 |
|---|---|
| 原理 | 按种子点把空间切成"最近种子"的cell |
| 用途 | **防区自动分配**（每个小队分一块地）、"哪个单位离哪个伤害源最近" |
| 复杂度 | O(n log n)（Fortune） |
| 坑 | 动态重算贵——只在小队锚点变化时算，不要每帧算；用幂图（power diagram）可按兵力加权 |

### S5 泊松盘采样（Poisson Disk）

| 项 | 内容 |
|---|---|
| 原理 | 在区域内生成"任意两点间距 ≥ r"的均匀随机点 |
| 用途 | 生成哨位、巡逻点、生成式地图、检查点 |
| 复杂度 | O(n)（Bridson 算法） |
| 坑 | 边界处要裁剪；密度 r 应随部队规模自适应 |

### S6 Delaunay 三角化

| 项 | 内容 |
|---|---|
| 原理 | 最大化最小角的三角剖分，是 Voronoi 的对偶 |
| 用途 | **自适应邻接关系**（谁和谁真的相邻）、连通性检查、分割检测 |
| 复杂度 | O(n log n) |
| 坑 | 1000 单位每帧重算太贵；只在聚类结果变化时算 |

### S7 流场（Flow Field / Vector Field）

| 项 | 内容 |
|---|---|
| 原理 | 在粗网格上从目标做波前传播，每格存一个指向"上游"的单位矢量 |
| 用途 | **全局导航**。把"寻路"降级成"势场梯度"，供群体层当作 seek 力 |
| 复杂度 | O(cells)，与单位数无关——1000 单位共享一份 |
| 优势 | 天然支持动态障碍（建筑、封锁区）、无局部极小、无 A* 的路径膨胀 |
| 坑 | 目标频繁变更导致重算风暴 → 必须合并/节流（≥200 ms）；网格太细则内存大，太粗则贴墙穿模（需局部避障兜底） |

## 3. 群体层（Motion & Swarm）

### A0 先厘清：Boids 与 Couzin 是同一族，不是两个候选 ★

最常见的误解。严格说，**Couzin（2002）是 Boids 的一个特例（参数化）**，不是并列的另一个算法。
两者都是「局部邻域 + 自驱动粒子」模型，同样用排斥 / 对齐 / 吸引三原语，同样 O(n·k)。

|      | Boids (A1)           | Couzin (A3)                      |
| ---- | -------------------- | -------------------------------- |
| 力的整合 | **加权求和**，三力同时作用      | **互斥判定**，按距离由近到远 `if/elif`，只执行一个 |
| 可调参数 | 权重（力的大小）             | **半径**（在什么距离上做什么）                |
| 边界   | 连续（核衰减）              | 硬边界（同心环），在环边界上会抖                 |
| 速度更新 | 力 → 加速度 → 速度，**有惯性** | 方向取平均，**恒定速度**                   |
| 可扩展性 | **线性可叠加**，加力只是加一项    | **互斥结构难扩展**：加一个力就要先定优先级          |
| 理论   | 纯启发式，无保证             | 有解析结论（集体记忆、空间排序、知情者临界比例）         |

**真正的分界线只有两条**：

1. **求和 vs 优先**——Boids 在拥挤时分离与凝聚互相抵消（"打架"，手感发软）；Couzin 由最近的区一锤定音（决定性强，但在区边界抖）。
2. **惯性 vs 恒速**——RTS 需要重量感、可预判的转向、能加速能停，**必须用 Boids 的积分器**；论文版 Couzin 恒速瞬时转向，手感像滑冰。

**结论：不是二选一。** 当系统要挂 6~9 个力时，Couzin 的互斥结构根本加不进去（每加一个力都要重排优先级表）。正确做法是缝合：

> **用 A3 的「区语义」定每个力的作用半径**（参数少、语义直观、设计师能调）
> **+ 用 A1 的「加权求和 + 积分器」做整合**（可扩展、无抖动、有重量感）
> **+ 用 A3 的「偏好方向 / 少数知情者」提供引导通道**

### 3.1 软化 Couzin（softened zones）—— 推荐写法

把同心环的硬边界换成**权重核**，`if/elif` 就变成连续曲线，既能求和又保留语义：

| 力 | 权重核 | 峰值位置 |
|---|---|---|
| 分离 | `(1 − d/r_r)²`，仅 `d < r_r` | d → 0 |
| 对齐 | `[r_r, r_o]` 上的梯形窗 | 中距平台 |
| 凝聚 | `[r_o, r_a]` 上的钟形窗 | `(r_o + r_a)/2` |

再补一项 `w_pref · (preferredDir − v)` 作为"偏好方向"通道：无邻居时它接管，有邻居时按邻居数插值压制。

> **诚实说明**：Couzin 的独有贡献不是"知情者能引导群体"这个**现象**（加权 Boids 里给少数单位更高 seek 权重同样能实现），
> 而是①知情者**临界比例**的解析结论（低到 5~10% 仍有效），②"无邻居时用偏好方向"这个**明确通道**。
> 可玩效果不是它独有的，但它给了可调的抓手与理论依据。

### A1 Boids（Reynolds, 1987）

**原理**：三条局部规则加权——分离（不重叠）、对齐（同向）、凝聚（不散架）。

```
for u in units:
    N = kNearest(u, 7)                    # 见 A2
    F = 0
    F += w_sep · Σ_{n: d<r_sep}  (pᵤ − pₙ) / d²
    F += w_ali · (avg(vₙ) − vᵤ)
    F += w_coh · (avg(pₙ) − pᵤ)
    F += seek(flowField(u.p, u.target))    # 见 S7
    vᵤ = clamp(vᵤ + F·dt, maxSpeed)
    pᵤ = pᵤ + vᵤ·dt
```

**必须分半径**（原则 3）：

| 力 | 半径 | 游戏语义 |
|---|---|---|
| 分离 | 1.2 × 单位直径 | 纪律 |
| 对齐 | 3~4 × | 协同 |
| 凝聚 | 5~6 × | 凝聚 |

**坑**：同半径会打架；不加速度上限会有"爆冲"；不加大阻尼会一直抖。

### A2 拓扑交互（k-NN 邻域）★ 性价比最高

**原理**：真实椋鸟群用**最近 6~7 个同伴**定义邻居，而非固定半径（Ballerini et al., 2008, PNAS）。

**为什么必须做**：
- 固定半径在**密集处**邻居爆炸（O(n²) 退化、行为僵硬、单位被"挤死"）；
- 固定半径在**稀疏处**没有邻居（掉队单位失去全部社交力，变成孤魂）；
- k-NN 与**密度无关**，密集/稀疏行为一致，掉队单位仍被最近同伴牵引。

**实现**：网格粗筛 → 取 3×3 格内的候选 → 部分排序取前 k（k=7 时用插入排序即可）。

**坑**：k 必须固定；对空邻域要退化处理（只剩 seek）；k-NN 的"最近"要包含自己以外的单位。

---

### A3 Couzin 区语义 + 少数知情个体（是 A1 的参数化，见 A0）

**原理**（Couzin et al., 2002, JTB；2005, Nature）：

```
邻居按距离分三区：
  z_o_r  排斥区（最近）  → 逃离
  z_o_o  定向区（中间）  → 对齐到平均方向
  z_o_a  吸引区（最远）  → 靠近

if 排斥区内有单位:      只执行排斥
elif 定向区内有单位:    对齐到 avg(direction)
elif 吸引区内有单位:    靠近
else:                  按自身"偏好方向"前进
```

**"少数知情个体"**（Couzin et al., 2005）：若只有少数个体知道目标方向，它们用偏好方向代替平均方向，**整个群体会被引导过去**——知情者比例低到 5~10% 仍有效。

**游戏价值**：玩家只需给 **1~2 个"知情者"** 下令，其余单位靠定向区传播并跟随。
→ 天然替代"框选 40 个单位 + 右键"，且有传播延迟、有队形、有重量感。

**坑**：知情者比例 > 20% 就退化成"全体寻路"（低操作量靠的是**少给指令**）；需要给传播一点"延迟"才自然（每帧只更新部分邻居）。

### A4 ORCA / RVO（van den Berg et al., 2008 / 2011）

**原理**：为每个移动体计算"速度障碍"——若双方保持当前相对速度将在 τ 时间内碰撞，则在一个半平面外选新速度；多邻居时对所有半平面做线性规划，取最接近期望速度的可行解。

**用途**：**保证不穿模、不堵死**。让 Boids 敢开高速度、敢用大分离半径。

**复杂度**：O(n·k) 次线性规划（每个邻居一个半平面）。

**坑**：千单位时是性能热点 → 分组算、只对最近 10~20 个邻居做；ORCA 的"礼貌"特性会导致**群体在窄口犹豫**，需配合流场或指定优先通行权。

### A5 备选算法（按场景取用）

| 算法 | 原理一句话 | 适合 | 不适合 |
|---|---|---|---|
| **Vicsek**（1995） | 取邻域平均方向 + 噪声，恒速运动 | 最便宜的"同向协同"；有全局有序的相变现象 | 需要队形时 |
| **Cucker–Smale**（2007） | 速度对齐，权重 `K/(σ+d²)^β` 随距离衰减；β<1/2 时证明收敛 | 平滑无抖的长途行军 | 需要快速响应时太"软" |
| **Social Force**（Helbing, 1995） | 驱动力 + 指数衰减排斥力 + 障碍力 | 溃败、挤窄口的真实混乱感 | 正常行军太黏 |
| **Continuum Crowds**（Treuille, 2006） | 把人群当流体，解最小代价势场 | 千单位大兵团的流体感 | 丢失个体性，不适合精英单位 |
| **Stigmergy 信息素** | 单位在网格上留下衰减痕迹，后续单位跟随 | 过窄口自动纵队、增援自动汇合、"走出来的路" | 需额外一张场，参数难调 |

### A6 ⛔ 明确不推荐：元启发式优化器

**PSO、ACO、人工蜂群、萤火虫、灰狼、遗传算法、神经进化、人工免疫**——
它们是**离线优化器**，不是**实时控制器**：需要"迭代到收敛"，而实时系统每帧只有 16 ms 且环境持续变化。

放进实时回路的结果必然是：**抖动、不可预测、不可调试、无法向玩家解释**。

**正确用途**：

| 用途 | 说明 |
|---|---|
| 离线调参 | Boids 权重、阵型参数、阈值的批量搜索 |
| 战前生成 | 关卡编队模板、AI 参数的进化搜索 |
| 自动对局 | 平衡性回归测试，用 GA 探索策略空间 |
| **唯一例外** | 蚁群 / 拍卖 / 匈牙利用于**低频目标分配**（1 Hz、n 小、允许 100 ms）是合理的 |

## 4. 小队层（Group Behavior & Decision）

### B1 响应阈值模型（Response Threshold Model, RTM）★ 最推荐先做

> **中文没有统一译名**：文献里称为 response threshold model / fixed threshold model /
> threshold-based task allocation。按"阈值响应模型"直译检索通常查不到，**用下列英文词**：
> `response threshold model` + `division of labor`、`fixed threshold model` social insects、
> `response threshold reinforcement`、`threshold-based task allocation` swarm robotics。
> ⚠️ 不要与社会学的 `threshold model`（Granovetter 1978，暴动/传染级联）混淆——那是另一套机制。

**出处**

| 文献                                                                                                                                                                                    | 内容                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| Bonabeau, Theraulaz, Deneubourg (1996). *Quantitative study of the fixed threshold model for the regulation of division of labour in insect societies*. Proc. R. Soc. B 263:1565–1569 | **固定阈值版**的原始论文        |
| Theraulaz, Bonabeau, Deneubourg (1998). *Response threshold reinforcements and division of labour in insect societies*. Proc. R. Soc. B 265:327–332                                   | **阈值可强化版**（会"学习"的版本）  |
| Bonabeau, Dorigo, Theraulaz (1999). *Swarm Intelligence: From Natural to Artificial Systems*, OUP，第 3 章                                                                               | **教科书级完整推导**，从这里入门最省力 |
| Robinson (1992). *Regulation of division of labor in insect societies*. Annu. Rev. Entomol. 37:637–665                                                                                | 生物学背景（阈值是真实的可测性状）     |
| Beshers & Fewell (2001). *Models of division of labor in social insects*. Annu. Rev. Entomol. 46:413–440                                                                              | 综述，横向比较多套分工模型         |

#### 原理

生物学观察：社会性昆虫（蜜蜂、蚂蚁、胡蜂）里，**个体开始做某件事所需要的刺激强度不同**。
这个临界值就是"响应阈值" θ。刺激来源是局部可测的（幼虫饥饿度、巢温、外敌信息素浓度）。

个体 i 面对任务 j，在刺激 S_j 下的**执行概率**：

```
P_ij = S_jⁿ / (S_jⁿ + θ_ijⁿ)          n ≥ 2（陡峭度），常取 2
```

- `S ≫ θ` → P → 1（刺激很强，几乎一定去做）
- `S ≪ θ` → P → 0（刺激很弱，几乎不做）
- 这是一个 **Hill 函数 / S 形曲线**——这也是它和 Utility AI 的血缘关系（见 B2）。

#### 关键：阈值必须"个体之间有差异"

- 若所有个体 θ 相同 → 群体行为是**全有或全无**（要么全员做，要么全员不做）。
- θ **异质** → 群体产生**分级响应**：
  - **低阈值个体** = 专家，常态下就干这活；
  - **高阈值个体** = **预备队**，只有刺激升到很高才被激活。
- 这正是"预备队自动投入"的算法来源：不需要指挥官下令，刺激上来了自己就上。

宏观性质：**群体投入量对需求近似线性响应**（活多一倍，干活的人差不多多一倍），且**有冗余**（损失几个个体，刺激上升，其他人自动补位）。

#### 两种变体

| 变体 | 规则 | 涌现什么 |
|---|---|---|
| **固定阈值**（1996） | θ 一旦设定不再变 | 稳定的分工，但对环境突变适应慢 |
| **阈值强化**（1998） | 做该任务时 `θ ← θ − δ`；不做时 `θ ← θ + φ`（遗忘），并夹在 `[θ_min, θ_max]` | **专业化 + 可塑性**：干得多的个体越来越擅长也越来越愿意干；环境变了则缓慢退化重分配 |

**"阈值强化"是本算法最被低估的部分**：它让单位**长出"习惯"**——一支长期打前锋的部队会真的变成前锋部队，撤下来休整后又会慢慢"忘掉"。这几乎不需要额外规则，是实现"单位有性格"的最便宜路径。

#### 搬到 RTS：必须改成确定性版本

原始模型是**概率切换**。游戏里不能这么用——非确定性的角色切换会让玩家觉得"不公平、不可预判"。

**改用确定性打分 + 滞回**（本质是把 Hill 函数当 utility 曲线用）：

```
每 200 ms，对每个单位：
    for role in [前排, 输出, 预备, 侦察, 撤离]:
        s[role] = 归一化刺激(unit, role)        # 0..1，只读局部感知
        score[role] = s[role]ⁿ / (s[role]ⁿ + θ[role]ⁿ)
    best = argmax(score)
    if score[best] > score[current] × 1.15  and  在任时长 > 0.5 s:
        switch(current → best)
```

`× 1.15` 与 `0.5 s` 是**滞回**，防区边界抖动。若仍想要随机性，用**带种子的 RNG**，保证可复现。

#### 刺激与阈值的一个具体配置（可直接试）

| 角色 | 刺激 s（局部可测） | 阈值调制 |
|---|---|---|
| **前排** | 局部受伤速率 / 接触敌人数 | 坦克兵种 θ↓、老兵 θ↓ |
| **输出** | 射程内敌人数 / 视野内敌人数 | 远程兵种 θ↓ |
| **预备** | "前排占比"的缺口（邻域统计） | 高速兵种 θ↓ |
| **侦察** | 周围迷雾比例 / 未知区域 | 轻装兵种 θ↓ |
| **撤离** | 自身血量低 + 附近队友少 | 士气低时 θ↓ |

**异质性来源**：兵种 archetype、老兵度、士气、体型归一化。**至少要有两个来源**，否则分工退化成"按兵种写死"。

**成本**：O(n)，每单位只读局部感知，无中央分配、无全局计算。

#### 坑

1. 阈值**不做体型/兵种归一化** → 大单位永远当前排。
2. 所有个体 θ 相同 → 全有或全无，看不到分级响应。
3. 用纯概率切换 → 不可复现、玩家不可预判。必须确定性 + 滞回。
4. 刺激用了**玩家看不见的全局变量** → 玩家无法推理部队为什么变阵，必须保证刺激是"画面上看得见的"（受伤、敌军数量、迷雾）。
5. 缺少"无角色"的兜底行为 → 全部 score 都低时单位发呆。
6. 阈值强化若不夹上下界 → 长期单向后阈值漂移到失效。

#### 检索与入门建议

1. 先读 Bonabeau/Dorigo/Theraulaz (1999) 第 3 章，一晚上能建立完整直觉。
2. 再读 1998 那篇的强化规则（只有几页）。
3. 代码实现极短（不到 50 行），先做**固定阈值版**，跑通角色分化，再加强化。

### B2 Utility AI（打分选择）

**原理**：给每个候选行为算一个分，取最高分。

```
score(进攻) = 兵力优势 × 激进度 − 损失率
score(固守) = 阵地价值 × 守备加成
score(后撤) = 损失率 × (1 − 士气) + 被包围程度
score(绕行) = 侧翼价值 × 机动余量
```

**用途**：**小队层的一个决定**，不是单位的很多决定。

**优势**：可解释（UI 能显示"因为损失 31% > 30%，选了后撤"）、可调（每项系数就是难度旋钮）、计算量小（每队每 0.5 s 一次）。

**坑**：评分项别超过 6 个；必须有滞回（新选项要领先 15~20% 才换），否则每 0.5 s 翻转。

---

### B3 包容架构（Subsumption, Brooks 1986）

**原理**：多个行为层并行运行，高层（更紧急）**抑制**低层的输出。

```
优先级（低 → 高）：
  追击目标  <  保持阵位  <  避免碰撞  <  脱离致命威胁
```

**用途**：个体"本能层"。保证任何情况下单位都不犯傻。

**优势**：极简、极鲁棒、**天然可解释**（下层一直在跑，只是被抑制）；比行为树轻得多。

**坑**：抑制关系不能成环；层数别超过 5；调试时要能单独观察每层输出。

---

### B4 Quorum 阈值共识

**原理**：每个个体独立判断"我要不要切换状态"；当**切换者的比例**超过 quorum `q` 时，集体状态翻转。

```
for u:
    if 我的局部判据 满足: 想切 = true
if count(想切) / n > q:  全队切换
```

**用途**：**士气崩溃、集体冲锋**。

**价值**：溃退不再是一个开关（"士气<30 就溃"），而是一个**有前兆、会传播、可能被督战阻止的过程**。

**坑**：每个单位都要投票，别用"全队平均"偷懒（那会丢掉相变）；`q` 通常 0.3~0.6；必须配滞回。

---

### B5 Voronoi 分区（防区自动分配）

**原理**：以小队锚点为种子做 Voronoi 划分，每个小队守自己那一块。

**用途**：玩家画一个圈，系统自动把防区切给各小队 → **不需要逐个摆位**。

**加权版**：用幂图（power diagram）按兵力加权，强队分到大区。

**坑**：见 S4。

---

### B6 拍卖 / Contract Net（Smith, 1980）

**原理**：目标"挂牌"，各单位根据代价出价（距离、方向、适性），最高出价者中标。

**用途**：**目标分配**（谁打谁）。低频、n 小、可解释。

**坑**：O(n_targets × n_bidders)，只在目标集变化时重算；需要"流拍"处理（无人出价则挂起）。

---

### B7 备选（加分项）

| 算法                                                   | 机制                    | 涌现出什么                      |
| ---------------------------------------------------- | --------------------- | -------------------------- |
| **自私羊群 / Predator-induced flocking**（Hamilton, 1971） | 每个个体想躲到"离最近威胁最远"的相对位置 | 被攻击时自动挤成密集球、边缘个体被"挤出"，无需拉扯 |
| **需求驱动 Agent**（弹药/疲劳/补给）                             | 行为由内部需求驱动             | 自动回补给、自动抢资源点、自然撤退          |
| **双稳态 + 滞回**                                         | 两个稳定状态 + 跳变阈值         | 进攻 ↔ 溃退之间的干净切换，边界不抖        |

## 5. 组合方案

### 5.1 最小可玩栈（五个算法打一局）

```
S1 空间哈希 + S7 流场
A1 Boids(k-NN) + A3 Couzin 知情者
B1 阈值响应 + B4 Quorum
```

这六个已经能产生：自然阵型、自然角色分化、自然过窄口、自然包抄、自然溃退。
**不需要任务系统、不需要授权等级、不需要阶段机。**

### 5.2 完整栈（按需叠加）

| 顺序  | 加什么           | 解决什么        | 何时才加     |
| --- | ------------- | ----------- | -------- |
| 1   | S1 + S2       | 邻域查询        | 一开始就要    |
| 2   | A1 + A2       | 成群、不重叠      | 一开始就要    |
| 3   | S7 流场         | 长距离不卡住      | 有复杂地形时   |
| 4   | A3 知情者        | 少指令指挥大军     | 单位数 > 20 |
| 5   | B1 阈值响应       | 角色自然分化      | 有兵种差异时   |
| 6   | A4 ORCA       | 绝不穿模/堵死     | 单位密度高时   |
| 7   | B2 Utility    | 小队自己决策      | 双方兵力接近时  |
| 8   | B4 Quorum     | 士气与溃退       | 需要"戏剧性"时 |
| 9   | S3 DBSCAN     | 小队/敌团识别（UI） | 需要小队徽章时  |
| 10  | S4/B5 Voronoi | 防区分配        | 有多点防守需求时 |

### 5.3 集中式 vs 去中心式：怎么选

| 需求特征 | 选集中式 | 选去中心式 |
|---|---|---|
| 决策频率 | 低（0.5~2 Hz） | 高（每帧） |
| 后果可解释性 | 要求高（要能说出为什么） | 不要求（是"本能"） |
| 规模 | 小队级（n<20） | 单位级（n 大） |
| 典型算法 | Utility AI、拍卖、Voronoi | 阈值响应、Boids、包容架构 |

**经验比例**：单位层 100% 去中心，小队层 1 次集中决策 + 全员去中心执行。

## 8. 陷阱总表

| # | 陷阱 | 症状 | 修法 |
|---|---|---|---|
| 1 | **无状态聚类的身份抖动** | 小队徽章每帧闪、加成时有时无 | 锚点匹配 + 软隶属 + 滞回；聚类只做观测，不做身份 |
| 2 | **用状态去稳定无状态** | 为"保持小队完整"而提高凝聚 → 永远不分裂，涌现被锁死 | 身份**不能**反调自己的成员构成 |
| 3 | **离散标签驱动数值** | 1 帧翻转导致属性阶跃 | 所有效果加 0.3~0.8 s 斜坡与独立滤波 |
| 4 | **三力同半径** | 分离和凝聚互相抵消，群体忽聚忽散 | 分半径 |
| 5 | **全局优化器进实时回路** | 抖动、不可预测、无法解释 | 移到离线；实时只留 1 Hz 以下的组合分配 |
| 6 | **k 不固定 / 无空邻域处理** | 行为随密度剧变 / 掉队单位失控 | k 固定；空邻域退化到 seek |
| 7 | **无加速度上限** | 单位"爆冲"、穿插 | 加速度/转向角速度双限 |
| 8 | **无滞回** | 每帧翻转，手感电子味 | 换边阈值 + 最小驻留时间 |
| 9 | **流场无节流** | 目标频繁变更 → 重算风暴 → 卡顿 | 合并目标 + ≥200 ms 节流 |
| 10 | **知情者比例过高** | 退化成"全体寻路"，失去低操作量 | ≤ 10~20% |
| 11 | **阈值未归一化** | 大单位永远当前排 | 按体型/兵种归一并调阈值 |
| 12 | **Utility 无滞回** | 每 0.5 s 决策翻转 | 新选项领先 15~20% 才换 |
