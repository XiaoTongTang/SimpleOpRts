# 04 · 待审清单（我认为可疑的 8 条）

> 这里不是"已判定要删"，而是**我自己的复查结论**：这些断言守的东西不像"游戏该有的行为"，
> 更像实现细节或调参数字。请重点看，然后决定保留 / 删除 / 改写。
> 每条都附了"业务语义版"的改写草案，方便对比。

## A. 钉常量 / 钉数字

### A1 — `W-01`（wall:58）「切进深度是 8 px」

- **现状**：`CHAMFER_DEPTH_PX === 8`。
- **问题**：8 是手感/调参数字，和"墙该切角"这条规则无关。改手感（比如觉得 8 px 太钝，想切 6 px）就要改测试。
- **业务语义版**：只断言"深度是正数，且不超过一格"。
  ```js
  ok("倒角深度是个正的实物尺寸", CHAMFER_DEPTH_PX > 0);
  ok("深度不超过一格", chamferDepthPx(4) <= 4);
  ```
  而"换格长不改切角"由 `W-03`（`chamferDepthPx(24) === chamferDepthPx(8)`，改成相对比较）守就够。

### A2 — `W-02`（wall:59）「默认 8 px 网格上正好切满一格（与沙盒一致）」

- **现状**：`chamferDepthPx(8) === 8`。
- **问题**：与 A1 重复，且再次钉住 8。
- **业务语义版**：删掉；如果要保留"默认格长下切满一格"这条描述，改成
  `chamferDepthPx(DEFAULT_CELL_SIZE) <= DEFAULT_CELL_SIZE`（不变量，不钉具体值）。

### A3 — `C-08`（cell-size:41）「格式基准格长没被改成可调项」（`MAP_FILE_CELL === 8`）

- **问题**：这是格式常量，属于"文件格式版本"层面的事，游戏运行时不需要它恒定。
- **业务语义版**：断言"文件没写 `cellSize` 时按其默认解释"就够了（已有 `C-38`），
  这条可删。

## B. 用内部编码当断言

### B1 — `W-08`（wall:70）「3×3 左上角格只切左上这一个角」（`mask === 1`）

- **问题**：`1` 是位掩码的 bit0。业务上只关心"哪几个角被切了"，不关心用哪个整数表示。
- **业务语义版**：用几何探针表达同一个意思（已有一半）：
  ```js
  ok("左上角被切掉", !insidePoly(corner, 5*C + 1, 5*C + 1));
  ok("另外三个角都在", …);
  ```
  这两条（`W-09` `W-10`）已经完整表达了规则，`W-08` 可删。

### B2 — `W-12`（wall:82）「1 格厚墙端头 mask = 左上 + 左下」（`mask === 9`）

- **问题**：`9` = bit0|bit3，纯编码。
- **业务语义版**：改成几何——
  ```js
  const end = getChamferedCellPolygon(m1, 4, 5);
  ok("端头上下两个角被切", !insidePoly(end, 4*C+1, 5*C+1) && !insidePoly(end, 4*C+1, 6*C-1));
  ok("端头右侧两个角还在", insidePoly(end, 5*C-1, 5*C+1) && insidePoly(end, 5*C-1, 6*C-1));
  ```

### B3 — `W-05` / `W-11`（wall:65 / 81）「…mask = 0（不切）」

- **问题**：同样是掩码，但这里 `0` 的语义是"不切"，比上面的情况温和一些。
- **业务语义版**：`W-07`（内部格左上角还在）已经表达了；两条 mask 断言可删，或与 `W-07` 合并。

### B4 — `W-17`（wall:107）「孤立单格 mask = 0」

- **问题**：同上。业务规则是"孤立单格不切、保留完整方块以便有碰撞"。
- **业务语义版**：只留 `W-18`（仍是完整方块）+ 四角都在的探针；`W-17` 可删。

## C. 断言写法不成立（不是"该不该测"，是"测错了"）

### C1 — `F-10`（flow-field:90）「方向不会直接指进墙里」

- **现状代码**：
  ```js
  const nx = 18 + left.x, ny = 4 + left.y;     // 格号 + 单位向量
  return m.isWall(Math.round(nx), Math.round(ny));
  ```
- **问题**：量纲错误。方向是**世界空间单位向量**（分量 ~0.6/0.8），格号是**格坐标**；
  相加之后再取整，实际查到的是 (19,5) 这种相邻格，几乎永远不是墙。所以这条断言"必然通过"，
  并没有验"方向不指进墙"。
- **业务语义版**（沿方向走一格，看落点）：
  ```js
  const wx = 18 * C + C/2, wy = 4 * C + C/2;          // 探测格的世界坐标
  const stepX = wx + left.x * C, stepY = wy + left.y * C;
  ok("沿方向走一格不落进墙里", !m.isWallAt(stepX, stepY));
  ```

## D. 内部状态 / 实现结构

### D1 — `F-26`（flow-field:162）「信标下完还没算（排队中）」（`flowQueue.length === 2`）

- **问题**：`flowQueue` 是内部队列结构，长度 = 2 依赖"一次命令把两支队伍都入队"的实现细节。
- **业务语义版**：只断言**可观察结果**——命令返回后尚未有任何小队拿到场：
  ```js
  ok("信标下完的当帧还没有场", !core.squads[a].flow && !core.squads[bIdx].flow);
  ```

### D2 — `F-33`（flow-field:179）「场地规模正确（cols×rows）」

- **问题**：数组尺寸是实现。
- **业务语义版**：删；如果担心越界，改成"在地图四角各取一次方向都不抛异常"（行为面）。

### D3 — `C-24`（cell-size:93）「格长没变就返回原图」（`regridMap(m8,8) === m8`）

- **问题**：对象同一性，纯实现。
- **业务语义版**：删，或改成"格长没变时墙逐格不变"（行为面）。

### D4 — `C-16`（cell-size:61）「快照能读到格长与网格」

- **问题**：那个 HUD 小标签已经按你要求删掉了，`snapshot().map` 现在**没有任何消费者**，
  这条是在验证一个死契约。
- **业务语义版**：删。如果将来要在界面上显示地图名/格长，再加回来（那时它才有意义）。

## E. 调参敏感阈值

### E1 — `F-36` / `F-37`（flow-field:233 / 235）「15 秒内到达」「无流场至少慢 1.4 倍」

- **问题**：改 Couzin 参数、巡航速度、船体速度都会让帧数漂；迁移期已经因为参数改动红过一次。
- **业务语义版**：
  - 保留 `F-35`（有流场能绕进去）——这条是**能力**断言，稳定。
  - 把"快多少倍"降级成 bench（`behavior.bench.mjs` 里打印数字），或把阈值放宽成
    "无流场时**至少不会更快**"（`noFlow.frames >= withFlow.frames`），这样只验方向不验幅度。
