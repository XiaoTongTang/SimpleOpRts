## 2. 这批测试怎么跑

- 每个文件都能单跑：`node test/wall.smoke.mjs`。文件内部自带 `ok()` / `eq()` / `near()` 计数器，
  打印 `ok`/`FAIL`，末尾 `process.exit(fail ? 1 : 0)`。
- `pnpm test` 是 20 个文件的 `&&` 串，任意一个非零退出就停。
- 因此**删断言不会影响其它文件**；删整个文件要同时从 `package.json` 的 `test` 串里去掉。

每条断言给了一个 ID（`W-xx` / `F-xx` / `C-xx`），表格里四列：

| 列 | 含义 |
|---|---|
| 断言原文 | 测试输出里会打印的那句中文 |
| 它守的业务规则 | 用"玩家能观察到的行为"来描述，不用实现细节 |

| 结论 | 留空 = 待你定 |

结论直接填四种之一即可：

- **保留** —— 守的是真规则，验法也站得住

- **改写** —— 规则对，验法不对（比如拿内部掩码位当断言）
- **降级** —— 挪去 bench / 手工看，不进 `pnpm test`

## 5. 一句话背景（评审时会用到）

- **地图格（8 px 默认）** 决定墙的离散精度、流场分辨率、倒角深度上限。
- **倒角**：把暴露在外的 90° 墙角磨成 45° 斜面，避免船贴角滑过时"顿一下"；
  深度是绝对像素（8 px），不随格长变，且不超过一格。
- **流场**：每支有信标的小队一张，按目标格共享缓存，每帧固定建 1 张（确定性要求）。
- **格长**：比例尺开关，唯一来源是 `map.js` 的 `DEFAULT_CELL_SIZE`；
  导入的地图文件里写的 `cellSize` 只用来解释"这张图原本多大"，不决定引擎格长。
