# 技术设计 · 流场通行成本（净空惩罚）

> 状态：**待评审**
> 日期：2026-11-15
> 归属：`design/261115_2流场通行成本/`
> 目标：让流场算出来的路径**不贴着墙走**，减少单位撞墙 / 蹭墙

---

## 0. 一句话

给墙边的格子加一点**通行代价**（离墙越近代价越高），再照常跑 Dijkstra。
代价只跟"这格离墙几格"有关，**与单位半径无关**，所以是纯几何的，不需要为每支队伍单独建场。

---

## 1. 决策：流场不考虑单位半径

你说得对，这里算半径既没用、又贵。三条理由：

1. **消费者是集群，不是单船**。流场给整支小队提供"往哪边走"的趋势；队形一横展就是 100+ px，
   单船半径 6~23 px 的那点差别被队形宽度淹没了。为它分档建场是精确到错误的层级。
2. **一档就够**：真要为半径服务，`FlowCache` 的键就得从 `地图版本:目标格` 变成
   `地图版本:目标格:半径档`，同目标的多支队伍不再共享，建场次数翻倍；而收益无法验证。
3. **它本来就不是防撞手段**：流场只给方向，不给刹车、不给避让。想让船不蹭墙，
   真正管用的是"近墙减速"（二期），半径写进寻路只是自我安慰。

**因此本设计里没有任何"半径"字样**：惩罚带宽度以**格**为单位（默认 3 格），
格长放大时它跟着放大——这与"格长 = 地图比例尺"的口径自洽（整张图放大，边距也一起放大）。

## 2. 算法

只改 `buildFlowField()` 一个函数，五步，其中第 2、3 步是新增的。

### 2.1 步骤

```
1. 建带一圈实心边的 solid[]                                （已有）
2. 净空距离变换：clearance[i] = 到最近墙格的 chamfer 距离     （新增）
3. 每格惩罚：pen[i] = max(0, B − clearance[i])              （新增，单位"格"）
4. 边权（Dijkstra 每步累加的那个数）：
   w(a→b) = len(a,b) · (1 + λ·(pen[a] + pen[b]) / (2B))      （改一行）
5. 方向回填：仍按 cost 下降最多 + 原有对齐 tie-break          （不变）
```

> 第 4 步的 `/B` 只是把惩罚**归一化到 0~1**：`pen ∈ [0, B]`，所以 `pen/B ∈ [0, 1]`，
> 整格的代价就是 `1 + λ·(0~1) = 1 ~ 1+λ`。少写这个 `/B`，λ 就得跟着 B 一起改，没法调。

### 2.2 净空距离变换

复用第 1 步已经建好的 `solid[]`（外扩一圈实心边），两趟 chamfer：

```js
// 正交 +2、对角 +3，单位是"半格"；clamp 到 2B 就够（再大也没有惩罚）
for (前向趟: 从上到下、左到右)  d[i] = min(d[i],
      d[i - PW] + 2, d[i - 1] + 2, d[i - PW - 1] + 3, d[i - PW + 1] + 3);
for (后向趟: 反向同样扫一遍)     d[i] = min(d[i], 反向四个邻居 + 2/+3);
```

- 墙格自身 `d = 0`；离墙 1 格的格心 `d ≈ 2`（半格单位），依此类推。
- 2-3 chamfer 与欧氏的相对误差 < 6%，我们只要"离墙越近越贵"的单调性，不需要精确。
- 一趟 O(n)，n = 37 500 时约 0.2~0.4 ms。

### 2.3 边缘代价

```js
const penOf = i => Math.max(0, B2 - d[i]);        // B2 = 2B，整数
const next = nodeCost + dir[2] * (1 + LAMBDA * (penOf(index) + penOf(ni)) * 0.5 / B2);
```

- `c = 1 + λ·pen/B ∈ [1, 1+λ]`，所以代价只被抬高最多 `λ` 倍。
- 乘法提到 `dir[2]` 外面：内层循环仍然是"一次数组读 + 两次乘加"，不引入除法。

### 2.4 方向回填（第二步）

流场是两步算出来的：

| 步 | 干什么 | 产出 |
|---|---|---|
| 1 | 从目标格做 Dijkstra | `cost[]`：每格"走到目标还要多少代价"**（标量势场）** |
| 2 | **方向回填**：对每格挑一个"走一步最划算"的邻居，存成单位向量 | `dirX[] / dirY[]`：每格一支箭头**（向量场）** |

船每帧只做一件事：读自己脚下那格的箭头。所以第 2 步是把"代价"翻译成"方向"的唯一环节，
等价于**找回 Dijkstra 的前驱（predecessor）**——只是不存前驱指针，而是当场比较 8 个邻居重新选一次。

现在的比较式（`flow-field.js` 回填段）：

```js
score = (cost[ni] + len(a,b)) * tl - dot · INV_LEN · TIE
```

- `cost[ni] + len` —— 经过邻居 `ni` 走一步之后的总代价，取最小 = 下坡最多（`len` 是 1 或 √2）
- `tl` —— 到目标的直线距离，只用来把后面那个 tie 项缩成**相对**的 1e-4 量级
- `TIE` 项 —— 候选几乎相等时，优先朝"对着目标"的方向（不加会走出 36° 的锯齿）

### 2.5 一个一致性问题（待评审第 4 点）

Dijkstra 累加的是**加权**步长 `w = len·(1 + λ·pen/B)`，而回填比较用的是**几何**步长 `len`。
两套度量不一致，后果是：

- 在惩罚带里，回填会系统性地偏向"低 `cost` 但很贵（靠墙）"的邻居 → **箭头略微指回墙边**，
  正好抵消我们要的效果；
- 严格说还可能挑到一个"加权意义上并不下坡"的邻居，让局部势场不再单调。

误差量级是每步 `≤ λ·len`（λ=0.25 时不到 1/4 格长），单格不起眼，但在墙边是**系统性**的。

**建议**：回填也用同一个 `w`（多一次乘法），保持对齐 tie-break 不变。
不推荐"在 Dijkstra 里直接记前驱向量"——那会绕开对齐 tie-break（36° 锯齿那个坑），还要多 37.5 KB。

## 3. 参数

| 参数  | 含义       | 建议       | 作用                    |
| --- | -------- | -------- | --------------------- |
| `B` | 惩罚带宽度（格） | **3**    | 离墙 ≥ 3 格的格不加价；一般取 2~4 |
| `λ` | 最大加权幅度   | **0.25** | 贴墙格比开阔格贵 25%          |

两个参数都只影响"路径多愿意离墙远一点"，不影响可达性、不影响拓扑。

### 3.1 `B` 和 `λ` 各管什么（可以心算的判据）

`B` 管**范围**：从墙算起，`B` 格以内才加价，`B` 格以外完全不加价（那里的格子和现在一模一样）。
`λ` 管**力度**：贴墙格比开阔格贵多少（`λ=0.25` → 贵 25%）。

`B = 3, λ = 0.25` 时每格的具体数：

| 离墙几格 | clearance | pen | 每格代价 |
|---:|---:|---:|---:|
| 0（墙） | 0 | 3 | 1.25（走不到） |
| 1 | 1 | 2 | **1.167** |
| 2 | 2 | 1 | 1.083 |
| ≥ 3 | ≥ 3 | 0 | 1.000 |

**"值不值得绕出来"的判据**：贴墙走一段长 `L`，比走开阔地每格贵 `λ·pen/B ≈ 0.167`；
绕出来到 `B` 格外再绕回去，多走约 `2(√2−1)·B ≈ 2.5` 格长度。
两者相等 → `L ≈ 15` 格。

也就是说：**贴墙段长于十几格时，流场会自动外弓；短于十几格时继续贴墙**（反正没便宜可占）。
这是个能直接调的数：想"更怕墙"，就把 `λ` 加大（判据长度变短）；想"只在长墙上让步"，就把 `λ` 调小。

### 3.2 标定方法（不猜，用数据选）

在一张"L 形墙 + 10 格宽走廊"的测试图上，把 (B, λ) ∈ {2,3,4} × {0.1, 0.2, 0.3, 0.5} 全跑一遍，量四个数：

1. 路径与墙的**最小距离**（越大越好）
2. **路径长度**相对 λ=0 的增幅（超过 15% 就是绕远了）
3. **贴墙帧率**（`collectCircleWallContacts` 深度 > 0 的帧占比）
4. **建场耗时**

取"最小距离明显变大、长度增幅 < 10%、耗时 < 9 ms"的那组。我预计落在 `B=3, λ=0.2~0.3`。

## 4. 这套改动**不会**动到的性质（这是它能安全落地的原因）

| 性质 | 是否改变 | 为什么 |
|---|---|---|
| 可达格集合 | **不变** | 只改权重、不改通行性；`c ∈ [1, 1+λ]` 恒有限正，`reachable` 一格都不差 |
| 确定性 | **不变** | 权重是纯整数/浮点的确定性函数，没有随机、没有时间依赖 |
| 缓存键 | **不变** | 不依赖半径、不依赖队伍 → `地图版本:目标格` 仍然够用 |
| 场地结构 | **不变** | 仍是 `cost/dirX/dirY`，`directionAt` 的双线性插值不用改 |
| 建场节奏 | **不变** | 仍是每帧固定 1 张（`FLOW_PER_FRAME = 1`） |
| 每格耗时 | +0.5~1 ms | 一维数组读 + 两次乘加；37 500 格 × 8 边 |

## 5. 它能改变什么、不能改变什么

### 5.1 会明显改善

- **凸角切角**：现在路径贴着墙角切线过去（点状最短路的性质），加了惩罚会外弓出约 1~3 格，
  船贴着墙角"顿一下"的情况减少。
- **8 邻域平局带来的贴墙抖动**：斜边 1.414 与直边 1+1 大量等值，现在由"朝目标更直"打破，
  在墙边容易选到贴墙那一支；加了惩罚后，等值比较里离墙远的那支更便宜。
- **方向的连续性**：墙边的 `dirX/dirY` 不再频繁反转，双线性插值出来的方向更稳。

### 5.2 **不会**改善（二期再说）

1. **接近墙时不减速**：流场只给方向。船 96 px/s、dt=1/60 一帧 1.6 px，靠 `resolveUnitWall`
   事后把法向速度投影掉 → 仍会蹭。要治需要"近墙减速"或"墙当静态邻居"的斥力。
2. **队形宽度**：小队横展 100+ px，惩罚带只有 3 格 = 24 px（cell 8 时）。
   队形外沿的船本来就落在带内，惩罚改不了它的位置。
3. **窄缝**：1~2 格宽的缝仍然"可通行且很贵"；惩罚不会把它判死（这是刻意的，
   判死需要按半径膨胀，那是另一种取舍）。

> 一句话：本设计把"该走哪条线"修正了，**没有**修正"这条线上能不能走准"。

## 8. 请评审的四点

1. **只做净空加权，不做半径相关的任何东西** —— 认可否？（我按"认可"写的） 认可
2. **`B = 3 格`、`λ = 0.25`** 作为起手默认值，然后在 §3.2 扫描表里定档 —— 认可否？ B=6, λ=0.4
3. **明确把"近墙减速/避让力"划到二期**，本次只交"路径更居中" —— 认可否？ 近墙减速/避让力永远不会做，不用排二期（我已验证过这个技术，结论是造成严重的鸟群靠墙抖动）
4. **方向回填要不要也用加权边？**
   现在回填比较的是 `cost[ni] + len`，而 Dijkstra 累加的是 `len·(1 + λ·pen)`。
   两者差一个 `(1 + λ·pen)` 的因子，所以回填有可能选中"代价最低但很贵"的邻居。
   我建议**回填也用同一个 `w`**（多一次乘法，换自洽）；也可以保持现状（省一次乘法，
   方向只会略微偏向带内，不影响可达性）。倾向：**用 `w`**。

## 9. 附：为什么"不按半径算"在理论上也站得住

最短路问题的解只依赖**可行域**和**代价函数**，与"谁会走这条路"无关。
半径属于"追踪轨迹时的物理约束"，它应该出现在
(a) 碰撞求解（已有，`reachCells = ceil(radius/cellSize)`），
(b) 减速/避让（二期），
而不是出现在"路径规划"的代价函数里 —— 除非你要做的是"按半径膨胀的硬可行域"，
那是另一个决定（D3 已否掉）。

所以本设计在层级划分上是干净的：**流场负责几何趋势，碰撞负责物理约束，力模型负责实际跟踪。**
