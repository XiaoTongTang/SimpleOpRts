> 状态：**已实现（2026-11-15）**，实现记录与实测见 §13
> 日期：2026-11-15
> 归属：`design/261115_2流场通行成本/`

---

## 0. 可行性结论：**可行**，但有三个前提

**可行。** 它和已有的净空成本是同一份几何（离墙距离），只是用法不同：

| | 有信标 | 无信标（本设计） |
|---|---|---|
| 要解决的问题 | 绕行时别贴着墙走 | 闲逛时别蹭到墙上 |
| 场的内容 | 到目标的**代价** + 每格方向 | **只有"离墙方向"**，且只在 B 格带内 |
| 场的数量 | 每个目标格一张（每队可能各一张） | **每张地图一张**（静态，与目标无关） |
| 重建时机 | 下新命令时 | 换图时（`map.rev` 变） |
| 谁消费 | `sq.goal` 存在的小队 | `sq.goal` 不存在的小队 |

三个前提（不满足就会变成"贴墙抖动"）：

1. **必须是"静态场"而不是"相互作用"**：场只随位置变化，不随单位、不随速度、不随别的小队。
   力的方向来自静态几何，因此没有"力改速度 → 速度又改力"的回路。
2. **力的大小是常数**（进带就给固定值，不按离墙距离加权、也不按速度加权）。
   抖动的成因是"力由一个会变的量算出来"的反馈环，不是"力在带边界上突变"（详见 §5）。
3. **进"环境力"槽，不进"命令力"槽**：`group-layer.js` 里 `wx/wy` 是环境力，
   不参与服从度 α 的统计（现有注释："环境力（边界）不参与"）。避墙属于环境，不该算成"听命令"。

---

## 1. 为什么不做成 `sq.flow`

`sq.flow` 的语义是"到某个目标的流场"，`directionAt(sq.flow, …)` 被**命令通道**消费，
并且 `FlowCache` 按 `目标格` 共享。把"避墙场"塞进去会破坏三件事：

- 没有目标就没有 key，缓存语义崩掉；
- 命令通道的方向会被替换成"离墙方向"，等于给闲着的小队下了一条假命令（`cmdPull` 会变成 1）；
- 服从度 α 会被污染（本来没有命令的小队会显示"很听话"）。

所以：**新增一个独立的地图级静态场 `avoidField`**，单独走环境力。

## 2. 场怎么算（每张地图一次）

### 2.1 数据结构

```js
// core.avoidField（按 map.rev 缓存，换图才重建）
{ rev, cols, rows, cellSize,
  ax, ay }       // Float32Array(n)：每格的"离墙方向"单位向量；带外为 0,0
```

### 2.2 步骤

```
1. 对每个墙格，向半径 B 内的空地格"泼"一份斥力：
       g = 该格中心 − 墙格中心          （世界坐标，px）
       wgt = 1 / max(1, |g|/cellSize)²   （离得越近权重越大，和船与船分离同一个公式）
       acc += g / |g| · wgt
   复杂度：墙格数 × (2B+1)² ≈ 2 万 × 169 ≈ 340 万次，一次性 ~3~6 ms
2. 归一化： ax,ay = normalize(acc)（acc 为 0 的格保持 0,0 —— 这就是"带外没有场"）
3. 带外清空： d = 到最近墙的距离（格）；d >= B 的格强制 ax = ay = 0
```

**没有权重这一步。** 归一化之后每格都是**单位向量**，力的大小由常数 `G.wallAvoidForce` 决定：
进带就推、出带就不推，与离墙 1 格还是 5 格无关（决策理由见 §5）。

**为什么要用"多墙叠加"而不是"最近墙的法向"**：凹角处（两条墙夹 90°）最近墙会跳变，
单位正好站在角平分线上时，法向会左右翻 —— 那是方向不连续的经典来源。
多墙叠加在平分线上是两侧对称相加，天然给出**角平分线方向**，连续、不跳。

### 2.3 距离可以从同一趟里拿

`flow-field.js` 的净空距离变换（两趟 chamfer）已经算过 `d`，可以抽成一个公共函数
`clearanceField(map, maxCells)`，两处（通行成本 / 避墙场）共用，避免两份几何。

## 3. 怎么用（力模型里的一行）

在 `group-layer.stepUnits()` 里，**只对没有命令点的小队**追加环境力：

```js
// 环境力槽（wx/wy）—— 和 boost 同一个桶，不进服从度
if (!sq.goal && avoid && G.wallAvoidForce > 0) {
  const i = 脚下那格（夹到界内）;
  if (avoid.ax[i] !== 0 || avoid.ay[i] !== 0) {     // 带内才有力
    wx += G.wallAvoidForce * avoid.ax[i];           // 恒定大小 × 单位方向
    wy += G.wallAvoidForce * avoid.ay[i];
  }
}
```

- `stepUnits(...)` 末尾加一个可选参数 `avoid = null`（现有调用方不传 → 行为完全不变）。
- 查表用**最近格**就够（力是常数，不随距离变化，不需要插值）。
- **不动** `boost`（低频助推仍然无条件生效，游走设计不变）、**不动** `resolveUnitWall`
  （硬碰撞仍然是最后一道保证）。

### 3.1 为什么只在"没有信标"时生效

有信标的小队已经在读一张**带通行成本**的流场，路径本来就离墙 ≥ B 格；
再叠一个"离墙推力"会和寻路方向打架（窄走廊里路径合法地贴着墙走，推力却要把它推开）
→ 这正是抖动的高发组合。**两者取一**：有信标走寻路，没信标走避墙。

## 4. 参数

| 参数                 | 位置                             | 建议初值   | 说明                                        |
| ------------------ | ------------------------------ | ------ | ----------------------------------------- |
| `B`                | 复用 `CLEARANCE_BAND_CELLS = 6`  | 6 格    | 和通行成本同一个带宽，避免两套几何                         |
| `G.wallAvoidForce` | 全局参数（`core.G`，可在阵型编辑的"全局参数"里调） | **40** | 与 `boostForce = 40` 同量级：足够把船推离墙，又不至于压过社交力 |

标定方法：一张带长墙的地图，让 4 支无信标小队闲逛 60 秒，量
①贴墙帧率 ②朝向 σ（抖动）③平均离墙格数 ④小队质心漂移距离（别把队伍挤成一团）。
目标是 ①③ 明显改善、②基本不变、④变化 < 20%。

---

## 5. 为什么不抖动（按 2026-11-15 的决策）

**抖动的成因不是"力在带边界突变"，而是"力由一个本身会变的量算出来"**：
力改变速度 → 速度又反过来改变力 → 两个反馈叠起来，振幅越来越大。
常数力没有这个回路：幅度不变、方向只由**位置**决定（静态几何），所以不会自激。

本设计因此做三件事，都指向"去掉反馈"：

| 做法 | 去掉的是哪个回路 |
|---|---|
| 力的大小是**常数**（不乘距离权重、不乘速度、不乘队形状态） | 力 ↔ 速度 的互相放大 |
| 方向来自**静态场**（只随位置变，且由多墙叠加保证连续） | 力 ↔ 位置微动 的方向翻转 |
| 只在 `!sq.goal` 生效 | 力 ↔ 寻路方向 的互相拉扯 |

代价（明确接受）：力在 `d = B` 边界上是**阶跃**的 —— 跨过边界，力突然出现/消失。
按上述判断，常数力的阶跃不会累积成震荡：单位被推出去就不再受力，要么继续按朝向游走，
要么过一会儿再飘回来，是一个慢过程（跨过 6 格带宽要 0.5 秒以上），不是高频抖动。

## 6. 成本

| 项 | 量级 |
|---|---|
| 建场（每张地图一次） | 3~6 ms（泼洒 340 万次），换图/重开时发生，不在帧内 |
| 每帧每单位 | 1 次下标 + 2 次乘加（只有无信标小队） |
| 内存 | 2 个 Float32Array(n)：250×150 时约 300 KB |

> 默认战场是空图（没有墙）→ 建出来全是 0，可以直接跳过（判"地图里一格墙都没有"）。

## 7. 与现有系统的关系

| 项 | 影响 |
|---|---|
| `FlowCache` / `sq.flow` | **不变**（避墙场不参与缓存、不占目标格） |
| 确定性 | 不变（静态、无随机、无时间依赖） |
| 服从度 α | 不变（环境力不计入分子分母） |
| `boost` 游走设计 | 不变（不改它的触发条件） |
| 硬碰撞 | 不变（`resolveUnitWall` 仍是最后一道） |
| 与通行成本的关系 | 互补：有信标用寻路成本，无信标用避墙力 |

## 8. 明确不做

- 不做近墙减速（已验证会造成抖动）。
- 不做按半径膨胀。
- 不给"有信标但流场还没算好"的小队叠这个力（那一两帧的直线方向不需要它）。
- 不把避墙力计入 `alpha` / 服从度统计。

## 9. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 无信标小队被墙"赶"到场地中间，分布变集中 | 力是长期的（一直闲逛就一直在推） | 只在 B 格内生效；标定时看"质心漂移" |
| 窄走廊里无信标小队被两侧夹住 | 两侧对称 → 合力≈0，其实是被"扶正" | 可接受；若发现卡住，`B` 降档 |
| 泼洒法在大片墙（如整面边框）上成本上升 | 墙格数 × 169 | 一次性；超过阈值就退化成"最近墙法向 + 平滑两趟" |
| 与 `boost` 同向时速度上限被顶到 | `maxSpeedFactor` 有安全阀 | 观察是否常驻上限 |
| 带边界上力是阶跃的 | 跨过 `d = B` 力突然出现/消失 | 按 §5 接受；实测"每帧转向"没上升即可 |

## 10. 验收

| 用例 | 期望 |
|---|---|
| 有信标的小队 | 行为**一位不变**（不读避墙场） |
| 无信标小队 + 长墙 | 贴墙帧率相对无场时下降 ≥ 50% |
| 无信标小队 + 长墙 | 每帧转向（抖动代理）**不高于**无场时（不许复现抖动） |
| 空图（无墙） | 避墙场为全 0；行为与改动前逐位一致 |
| 确定性 | 同 seed 跑两次逐位相同 |
| 性能 | 建场 < 8 ms（一次性）；帧内无可测增量 |
| 带外 | 离墙 ≥ B 的格 `ax = ay = 0`（"其他区域没有流场方向"的直接断言） |
| 力的大小 | 带内任意格的力**都等于** `wallAvoidForce`（与 d 无关） |

### 13.2 实现时踩到的一个坑（值得记下来）

第一版只对 `map.walls` 里的墙格做泼洒 → **贴着场地边界的船完全不受力**，因为"越界即墙"
的那一圈不在 `map.walls` 里。测试的第一条断言（空图边缘要有方向）直接抓到了：`cells = 0`。

修法：泼洒也放到"带一圈实心边"的布局里做，外圈自动算墙；归一化时再拷回不带边的数组。

| 断言 | 实测 |

| 两次建场逐位相同 | ✔ |
| 无信标小队 240 帧后平均离墙 | **6.17 → 7.50 格**（开 40 的力） |

### 13.4 顺带修掉的一条老断言

`flow-field.smoke` 的「无流场明显更慢（至少 1.4 倍）」：加了净空成本（B=10、λ=1）之后，
流场为了离墙远一点会绕路，差距从 ~2.4 倍缩到 ~1.18 倍，1.4 倍的阈值挂了。
按"冒烟测试不该钉调参倍数"改成 **≥1.05 倍**（仍能证明"流场确实有用"），并在注释里写明原因。
