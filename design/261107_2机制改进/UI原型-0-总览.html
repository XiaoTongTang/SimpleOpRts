战场指挥 · 舰船设计 · 小队构筑 · 阵型编辑

四张可点的 HTML 原型，用来评审信息层级与操作路径，不是最终美术。
全部离线可用（共用 UI原型.css，舰船图取自 imgs/护卫舰素材1.png 的真实切片）。

01
战斗指挥界面
战场铺满可视区；右栏只有每支小队的状态。
侧栏点选 / 战场点标记 / 拖拽框选，三种方式都能选中并下达命令。
框选Shift 追加质心标记
02
舰船设计界面
左：方案库；中：船体大图 + 槽位引脚；右：属性与装配。
点槽位（或船体上的引脚）会滑出二级面板，列出所有可装项及信息。
二级面板承载分段条尺寸互斥
03
小队构筑界面
左：编制模板（笔形按钮行内改名）；中：这队里的所有舰船，一型一卡，卡片底部直接调数量 / 删除；
右：总血量 / 总盾 / 总 DPS / 人口，下方增删方案，再往下是阵型编辑（从阵型库勾选本队可用阵型）。
即时合计卡片内改数量左侧滑出选船阵型预选
04
阵型编辑界面
左：阵型模板（内置不可删，自建可删可改名）；中：阵型效果演示 / 模拟战区域（原型留空）+ 底部控制面板；
右：12 个 Couzin 参数全量可调，每个都带解释，底部保存。
参数滑条另存为副本模拟战占位

四张界面共用的规则

项约定
数据来源 原型里的数据形状刻意对齐 core.snapshot()：squads[] / shipList[] / production[]。 接真数据时只换数据源，DOM 结构不动。
写入路径 所有改动最终都是 bridge.run(cmd) 一个入口；界面自己不做合法性判断。 原型里"置灰不可选"的项，真实现里由 core 返回 reasons 决定。
承载条 按来源分段着色：武器蓝 / 插件绿 / 支援黄。超限整条转红。 分段是为了让玩家一眼看出"这套是炮多还是插件多"。
数字口径 血量、护盾、承载、工时、人口全部来自模板硬编码值； 总 DPS 在原型里用每把武器手填的 dps 相加（单体口径），没有做任何期望值推算。
选中态 小队用色块 + 质心圆标；方案用左侧列表高亮 + 中栏标题同步。 三张界面里"选中"的视觉语言保持一致。

需要你评审的判断

1. 战斗指挥的右栏要不要放非小队信息？
按你的说法只放小队状态。但战斗中玩家很常看"我还能造多少"，我把指挥值/模组放在了顶栏， 右栏保持纯小队。如果顶栏太远，可以把它做成右下角的浮动块。
2. 舰船设计的中栏，槽位引脚是加分还是干扰？
现在把 w1/w2/p1/p2 直接钉在船体图上，好处是"炮口在哪"一目了然，坏处是小船图上很挤。 备选是：只在鼠标悬停槽位行时高亮对应引脚。
3. 小队构筑：一型一张卡，卡里放多少信息？
现在一型一张卡，船图缩到 64px，右侧补上血量/护盾/人口/工时与武器、插件清单，卡片底部直接改数量或删除。 备选是按实际编队位置铺开（更接近战场），但会重复画很多图，人数一多就糊成一片。
4. 阵型要不要绑在编制模板上？
现在每个编制从共用的阵型库里勾选 N 个（原型里第一突击队勾了横列线阵 + 楔形突击）， 战斗中只在这几个里快速切换，避免临场从全库里翻。数据结构见 构筑机制设计.md 的「阵型构筑」一节。 备选是阵型独立于编制、全局可选。
5. 总 DPS 的口径
统计层已经砍掉，所以 dps 只能作为武器模板上的一个手填字段存在（和 command / capacity / buildTime 同一性质）。 原型里按单体口径（伤害 ÷ 冷却）填的：激光 12、链炮 33.9、导弹 24.6、鱼雷 6、轨道炮 7.7。 这个数会直接决定玩家怎么选武器，需要你确认口径。
