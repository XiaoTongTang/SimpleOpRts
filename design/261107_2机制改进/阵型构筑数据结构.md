# 阵型构筑数据结构设计（评审稿）

> 对应实现：`projPhase1/src/core/sim/squad-layer.js` 的 `P_DEFS`、`group-layer.js` 的力场合成、`templates.js` 的现有战斗群。
> 本文范围：**阵型模板的数据结构 + 与编制模板的引用 + 运行时应用**。不含 UI 细节。
> 已定决策：① 不做几何阵型（永远）；② 切换瞬间应用；③ 阵型带交战块（阵型 = 全部 Couzin 参数）；④ 内置阵型从现有战斗群提取；⑤ 不做校验、不做管理，队形散开就散开。

---

## 1. 阵型模板 = 一整套 Couzin 参数

集群移动是 **Couzin 软化力场**：每帧把 6 种力加权求和，积分出速度。

```
社交力：分离 wSep · 对齐 wAli · 凝聚 wCoh
命令力：omega × wCmd（朝 goal）
战斗力：威胁 wThreat（r4 内排斥敌人）· 寻敌 wSeek（r4~r5 内吸向敌人）
半径：  rRep 排斥 · rOri 对齐 · rAtt 凝聚上限 · r4 威胁区 · r5 感知
```

**阵型模板 = 这 12 个参数的一整套取值**，字段名与 `sq.p` 完全一致，应用时就是 `Object.assign(sq.p, tpl.p)`。

| # | 决策 | 后果 |
|---|---|---|
| 1 | **不做几何阵型，永远不做** | 模板里没有 `offsets` / `geometry` / `rotate`；形状是涌现的，模板名只是意图标签 |
| 2 | **切换阵型瞬间应用** | 不做 0.3 s 插值，`setFormation()` 直接写 `sq.p` |
| 3 | **阵型带交战块** | 不拆"阵型 / 接敌策略"两种模板；阵型 = 全部 Couzin 参数 |
| 4 | **内置阵型从现有战斗群提取** | 见 §3，不自己编数值 |
| 5 | **不做校验、不做管理** | 没有 `validateFormation()`，没有半径随人数缩放；队形散开就散开，长成什么样算什么 |

第 5 条的具体含义：

- 半径是**绝对像素**，不随编制人数缩放。60 艘的队用 15 艘调出来的半径，队形自然会摊开——接受。
- 加载时不做任何范围检查、不检查 `rRep ≤ rOri < rAtt ≤ r5` 之类的顺序关系。数值照抄源码，源码本来就是这个顺序，写错了就是写错了。
- 不需要"阵型管理"：没有合法/非法状态，没有 reasons 回传，没有置灰。

## 2. 字段表

```js
{
  id:    "form.standard",          // string  唯一键，永不改名
  name:  "标准间距集群阵型",        // string  显示名
  desc:  "蜂群战斗群的站位 · 密集整齐", // string  UI 副标题
  from:  "swarm",                  // string  来源战斗群 key（仅内置阵型有，便于追溯）
  p: {                             // 12 个 Couzin 参数，键名与 P_DEFS 一致
    wSep: 1.50, wAli: 0.95, wCoh: 1.15,
    omega: 1.10, wCmd: 1.20,
    rRep: 17, rOri: 46, rAtt: 86,
    wThreat: 1.50, wSeek: 1.50,
    r4: 80, r5: 300
  },
  source: "builtin",               // enum  builtin | player
  meta:   { createdAt, updatedAt }
}
```

| 字段 | 说明 |
|---|---|
| `p` | 12 个参数一次给全，切阵型时整块覆盖（不做部分覆盖：否则切 A 再切 B 的结果会依赖历史值） |
| `from` | 只给内置阵型用，标注它是从哪个战斗群抄来的，改数值时能回去对照 |
| `source` | `builtin` 不可删不可改；`player` 可改可删 |

**不给 `hp / shield / regen / members`**：这些在 `templates.js` 的战斗群 `p` 里确实存在（那是**敌人战斗群模板**，打包了阵型 + 兵力 + 血量），但玩家的阵型模板只取阵型那 12 项。`members` 是运行时统计出来的实际人数，不是可配项。

四个阵型的战术性格（直接来自源码注释，改数值时别改跑偏）：

| 阵型 | 一句话 |
|---|---|
| 标准间距集群 | 密集整齐、凝聚强、个体脆 —— **基准阵型** |

## 4. 运行时应用（瞬间生效）

```js
core.setFormation(squadId, formId) {
  const tpl = FORMATIONS[formId];
  Object.assign(sq.p, tpl.p);       // 12 个参数一次性写进去，下一帧生效
  sq.formationId = formId;          // 只用于 UI 显示
}
```

- **不插值、不留过渡**（决策 2）。`wSep` 从 1.50 跳到 1.00 会让队形在一帧内重排，这是可接受的代价；如果实测观感太硬，唯一的修改点是这里，别把插值逻辑散到 L1。
- **不重建实体**：位置、速度、武器冷却全部保留，切阵型不该让部队停火或跳位。
- 只改参数，不涉及资源，不需要事务，也没有失败分支。
- 战斗中快捷键 `1..4` 对应 `SquadTemplate.formations[0..3]`。

## 5. 与小队编制模板的引用

```js
{
  id: "squad.tpl_0001", name: "第一突击队",
  entries: [ { ship: "ship.std_falcon", n: 16 }, { ship: "ship.std_bulwark", n: 6 } ],
  formations: ["form.standard", "form.guerrilla", "form.wide"],   // 有序，[0] 是默认
  meta: { createdAt, updatedAt }
}
```

| 规则 | 内容 |
|---|---|
| 顺序 | `formations[0]` 是新建小队时的默认阵型 |
| 数量 | 最多 4 个（`MAX_FORMATION_SLOTS = 4`，对应快捷键 1~4） |
| 空 | 允许 `[]`，此时沿用 `P_DEFS` 默认值（等价于"没配阵型"），不垫一个假的内置阵型 |
| 删除保护 | 删阵型模板时若被引用，拒绝并返回引用者名单 |

`formations` 只是引用：模板数值改了，引用它的小队下次切换即生效，不用改编制。

---

## 6. 硬原则：阵型模板不许改战斗力

只能写 `p` 里那 12 个键。**不能**出现 `hp`、`regen`、`shield`、`members`、`fireRate`、`damage`。

阵型是免费且零成本切换的，一旦能改数值，最优解就变成"找个数值最高的阵型永远不切"，机制退化成一件装备。这是一条数据结构约定，不是运行时检查——写代码时不往 `p` 里塞这些字段就行。

## 7. 阵营同构：玩家和 NPC 用同一张表

原则：**没有任何"玩家专属"或"NPC 专属"的配置项**。阵营 0 和阵营 1 是平等的两个阵营，NPC 只是"由 AI 来填这张表"，不是"用另一张表"。

对本文的直接后果：

- 阵型表**没有 owner / faction 字段**，任何阵营的小队都从同一张表里选；
- `templates.js` 里那套"敌方战斗群"打包模板要删掉：它把「阵型 + 兵力 + 血量 + 武器」打成一个对象，等于给 NPC 开了一条玩家走不了的路；
- 阵型数值已抽到 §3 的 4 条，兵力归编制模板、血量/护盾/武器归舰船模板 —— 这三样两边本来就都有。

`sim/templates.js` 的 `TEMPLATES`（蜂群/圣盾/游击/突击/要塞/游隼）和 `LOOSE_SQUAD` 目前**没有任何模块 import**，是历史遗留的死代码：早期"敌方用战斗群模板、玩家用舰船模板"的产物。删掉它不影响任何运行行为。

同批机制的排查结果（都是"玩家 vs NPC 不对称"的味道，记录在此，不阻塞阵型落地）：

| 位置 | 问题 |
|---|---|
| `sim/templates.js` | 打包的敌方模板 + 死代码，见上 |
| `core.js` `spawnAll()` / `this.build` | 构筑对象只有一份，蓝红 10 个小队挤在同一个 `build` 里；而 `production` 已经是 per-faction |
| `core.js` / `ship-library.js` | 舰船方案库只有一份（`createLibrary()`），两阵营共用；NPC 没有自己的方案库 |
| `state.js` `createBuild()` | 写死 `i < 4 ? 0 : i < 8 ? 1 : …` 的 4+4+2 分配 |
| `ui.js:284` | `find(p => p.faction === 0)` 写死"玩家的生产线"，看不到敌方 |
| `weapons.js` `towermissile` | 注释写"玩家装不上去"，语义应是与阵营无关的"塔挂载专用" |
| `战舰构筑数据结构.md` | 解锁记录叫 `PlayerCatalog`、方案 id 前缀 `ship.usr_`，隐含"只有玩家有" |

阵型表本身不受影响（它本来就是一张全局表），但要让"双阵营对局"成立，`build` 和 `ships` 得拆成 per-faction。

## 8. 落地方式（增量，不改现有行为）

1. 新增 `src/core/data/formation-templates.js`，按 §3 填 4 条，深冻结；
2. `P_DEFS` 一行不动 —— 阵型模板只是"一组预设值"，默认值仍是 `P_DEFS`；
3. `sim/templates.js` 的敌方战斗群模板**删除**：阵型数值已进阵型表，兵力归编制、血量归舰船模板，两边走同一条路；
4. 加 `setFormation()`，不做校验函数、不写单测断言顺序关系；
5. UI 侧（`UI原型-3-小队构筑.html` 的"阵型编辑"）只做勾选，不暴露 12 个滑条；滑条属于后续的硬核模式。
