## 2. 迁移三原则

**① core 不动。**
`node test/*.smoke.mjs` 全部不 import React/Pixi/DOM，这是护栏。任何一步改完跑一遍，绿了就说明模拟层没被碰。

**② 双实现并存 + URL 开关。**
迁移期不删旧代码，用参数切换：

```
/?ui=legacy       旧 DOM 面板
/?render=2d       旧 Canvas2D 渲染
（都不传 = 新实现）
```

验收哪一块就把哪一块的开关留到下一阶段再删。**这是整个计划里最重要的风险控制**：出问题一行 URL 就能回到能跑的状态。

**③ 只有一个主循环。**
`main.jsx` 的 rAF 依旧负责：`core.step → renderer.draw → bridge.tick → saveShips`。
**Pixi 的 `app.ticker` 必须 `stop()`**，只用 `app.renderer.render(app.stage)` 手动渲染。
（v8 里停 ticker 后画面会全黑，需要确认手动 render 生效——这条在 P7.3 第一件事就验。）

生产面板（生产线效率分配、排队进度）这次**没有出原型**，落地时先沿用旧位置的临时面板，等单独设计。

**关键约束**：

- 所有写操作仍然只走 `bridge.run(cmd)`，组件里**不判断合法性**；
- 装配预览走 `bridge.query({type:"previewFit"})`（已有）；
- 不要给列表加 `key={index}`，用 `squad.id` / `ship.id`；

**验收清单**（全部在浏览器里手点一遍）：

### P7.3 · Pixi 渲染器 · 2–2.5 人日

新增 `src/render/render-pixi.js`，继承 `WorldRenderer`：

| 元素      | 做法                                                                | 原因                               |
| ------- | ----------------------------------------------------------------- | -------------------------------- |
| 单位      | 一张三角纹理 + `ParticleContainer`（每个单位一个 sprite，每帧改 x/y/rotation/tint） | 800 个单位用 `Graphics` 逐个画会掉到 20fps |
| 护盾环     | 复用同一张环纹理，按护盾值调 alpha                                              | 同上                               |
| 血条      | **只画受伤的、且只在 zoom ≥ 0.8 时画**；用一张 1×1 白纹理拉伸                         | 满编 800 个全画血条 = 1600 个 quad       |
| 弹丸      | 小 sprite + 拖尾用 `Graphics` 池                                       | 数量中等                             |
| 特效（8 种） | `Graphics` 对象池，按类型预建，用完回收                                         | 复用而不是每帧 new                      |
| 战场边框    | 一个 `Graphics`，resize 时重建                                          | 静态                               |

**性能预算（硬指标）**：800 单位 + 300 弹丸 + 200 特效，1080p，**平均帧时 < 16.7ms**（用 `window.__PERF` 采 300 帧）。

**第一件事先验证**：`app.ticker.stop()` + 手动 `app.renderer.render(app.stage)` 能否正常出画。这条不通，整个方案要改成"把 core.step 挂到 Pixi ticker 上"（也能做，但要重排主循环）。

**验收**：`/?render=2d` 与默认实现截图接近（容差：颜色/位置一致，线宽可能有 1px 差）；帧时达标。

### P7.4 · 相机与交互 · 1–1.5 人日

| 功能 | 实现 |
|---|---|
| 滚轮缩放 | 以鼠标位置为锚点，`zoom ∈ [0.4, 3]` |
| 拖拽平移 | 中键或空格+左键；边界夹取 |
| 点选小队 | 点单位 → 找到 `unit.squad` → `actions.select(id)` |
| 平移/缩放的状态 | 放 **store**（`camera: {x, y, zoom}`），渲染器只读 |

现在 `getView().camera` 是 core 硬编码的 `{ox:0, oy:0, zoom:1}`。改为：**core 不再提供 camera**，渲染器从 store 读。改动只在渲染层与 `renderer.draw(view, camera)` 的签名，core 无感（这是"core 不动"的一次实测）。

**验收**：缩放后点选仍然准（屏幕→世界坐标换算正确）；拖到边界停住。

### P7.5 · 构筑界面落地 · 1.5–2 人日

三张界面的信息结构已经单独出原型，见同目录：

- `UI原型-1-战斗指挥.html` —— 战场铺满 + 右栏只放小队 + 点选/框选/侧栏三条选择路径
- `UI原型-2-舰船设计.html` —— 左方案库 / 中船体 + 槽位引脚 / 右属性与装配 + 二级装备面板
- `UI原型-3-小队构筑.html` —— 左编制模板 / 中全队舰船 / 右合计与增删数量
- `UI原型-0-总览.html` —— 三张的入口与共同约定

P7.5 的工作是**按原型实现**，不再另做信息设计。落地时要补的细节：

| 要加的 | 具体做法 |
|---|---|
| 承载分段条 | 武器蓝 / 插件绿 / 支援黄，超限整条转红 |
| 二级装备面板 | 点槽位滑出，按尺寸与承载过滤，不可装项置灰并给原因（原因来自 `computeShip` 的 reasons） |
| 蓝图未解锁 | 灰显 + 锁标记，`core.unlocked` 已支持校验 |
| 拖拽换装 | 从装备清单拖到槽位；拖拽只是另一种触发 `setShipFit` 的方式，校验仍在 core |
| 小队合计 | 总血量 / 总盾量 / 总 DPS / 人口，全部是 `count × 单舰值` 的简单求和 |

> **总 DPS 的口径**：统计层已砍掉，所以 `dps` 只能作为**武器模板上的手填字段**存在
> （和 `command` / `capacity` / `buildTime` 同一性质）。原型里按单体口径（伤害 ÷ 冷却）填：
> 激光 12、链炮 33.9、导弹 24.6、鱼雷 6、轨道炮 7.7。这个数会直接影响玩家选武器，需要单独确认。

**验收**：三张原型里的操作路径都能在真实现里走通；不可装项与超承载都能看到具体原因。

## 5. 风险表

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| Pixi 停 ticker 后黑屏 | 中 | 高 | P7.3 第一件事就验，备选方案：把 `core.step` 挂到 ticker |
| 逐单位 `Graphics` 性能崩 | 高 | 高 | 一律用纹理 + sprite/particle，`Graphics` 只给特效池 |
| React 重渲染风暴（10Hz 快照） | 中 | 中 | `useSnapshot` 用选择器订阅，面板粒度拆细 |
| 相机改造波及 core | 低 | 中 | camera 从 `getView()` 移除，只在渲染层与 store 之间走 |
| 迁移期两套 UI 状态不一致 | 中 | 低 | URL 开关切的是"整套"（ui + render 分别切），不混用 |
| Pixi 8 颜色解析（`hsl()`→黑） | 已踩过 | 中 | 颜色统一在渲染层转数字 hex，`Color` 只吃 0xRRGGBB |

## 6. 终态验收（整件事做完的标准）

1. 打开页面就是 React 面板 + Pixi 战场，URL 不需要任何参数；
2. 800 单位 + 300 弹丸 + 200 特效，平均帧时 < 16.7ms；
3. 全流程只靠鼠标完成：新建方案 → 拖武器 → 编队 → 排产 → 造出来；
4. 三张原型的操作路径全部走通：战斗（三条选择路径）/ 舰船设计（二级装备面板）/ 小队构筑（合计即时重算）；
5. `pnpm test` 全绿，且**没有一个测试文件 import React/Pixi/DOM**；
6. `?ui=legacy` / `?render=2d` 两个开关与旧代码一起删除，仓库里只剩一套实现。
