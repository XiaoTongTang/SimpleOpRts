
# 提出问题
如果玩家在游戏过程中，修改了舰船的配置和小队的编制；要如何处理新旧配置的问题？难道舰船方案变更后，就瞬间应用到所有舰船吗？

我们只允许玩家在“某一舰船方案未被建造”的情况下，才允许玩家修改这个舰船的方案；

一旦舰船被建造，则不允许修改；只有拆除所有已经建造的本方案舰船时才能修改舰船方案；而小队编制则可以随意在游戏过程中变更，只是变更后会自动剔除小队中不符合编制要求的舰船，使这些舰船其成为散兵；你认为这两个设计是否能满足配置变更的要求？

# 配置与战斗分层

我们游戏中，一共拥有如下这些 “配置” 与 “实例”：

| 概念         | 玩家改的是什么           | 修改规则                                                      |
| ---------- | ----------------- | --------------------------------------------------------- |
| 舰船方案       | 船体 / 槽位 / 插件 / 成本 | 如果战场上存在此方案对应的舰船，则禁止修改，禁止删除；建造过程中也算在场上；                    |
| 战场上已经造好的舰船 |                   |                                                           |
| 小队编制模板     | 有哪些船只，能使用的阵型      | 改动小队编制后，将战场上引用此小队编制模板的所有小队，剔除编制中不符合编制的舰船；并更改阵型为小队模板的默认阵型； |
| 战场上已经存在的小队 |                   |                                                           |

# 小队机制
小队可以引用编制模板，也可以是不引入编制模板（这样会失去吸收散兵的功能）

不引用编制模板的小队必须在手动创建时，选定一个或多个阵型，以供快速切换；


# 建造机制
母舰拥有多条生产线
每一条生产线都拥有 “待生产队列” 和 “当前正在建造的船只”
生产出来的舰船，自动并入散兵队；

生产线建造有两种模式，
- 一种是“快速建造”，即消耗预制模组直接建造；
- 一种就是一个个船排队慢慢造；

“一键建造一支小队”的功能，本质上是直接消耗对应数量的 “预制模组”，一次性把小队所需的所有舰船造出来，然后创建一个新小队，调用这只小队的“吸收散兵”功能； 

# 散兵机制

散兵池是一个收纳了所有未编队舰船的小队；玩家一样可以给散兵队下达命令信标
解散一只小队后，舰船自动回到散兵池中；
散兵小队不引用任何的 “编制” 是一只 “无编制小队”
母舰生产线生产出来的舰船，自动并入散兵队中；

# 指挥值机制
一个阵营所有已经建造出来的舰船，都会消耗母舰的指挥值



# 变更步骤：

1. **给舰船加身份**（`unit.shipId`，小队的共享参数改成逐舰编译）—— 这是所有后续机制的地基。
2. **散兵池 + 撤编/编入**（解散只是改编入关系，舰船数不变）。
3. **建造产出改流入散兵**，快速建造和排队两种模式都走同一条出口。
4. **编制模板层**（库、引用、追溯剔除 + 阵型重置）。
5. **方案锁定**（在役、在建、在队列三个计数，任一非零就拒改拒删；改名等身份字段不锁）。
6. **母舰实体**（可被打、死亡停产、存活才提供产能与指挥值上限）—— 这一步会牵动渲染、寻路、胜负判定，建议单独作为一个阶段。
