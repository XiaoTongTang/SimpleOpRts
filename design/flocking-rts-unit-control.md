# 《SimpleOpRTS》单位控制与编队系统设计
### 以鸟群算法（Boids）+ 密度聚类（DBSCAN）为内核的"低操作量、高战略深度"RTS

> **一句话定位**：玩家不再指挥"单位"，而是编辑"场与规则"；单位用局部规则自己活，小队用聚类自己成型；
> 玩家的操作量被制度性地限制（指挥带宽），于是胜负从"手速"转移到"预判与取舍"。

---

## 0. 结论先行：七个必须做对的决定

| # | 决定 | 为什么 |
|---|---|---|
| 1 | **命令的对象是"意图"，不是坐标** | 坐标命令天生要求玩家修正每一次偏差 → 微操的根源 |
| 2 | **纯 Boids 不足以寻路，必须是"流场 + Boids"混合** | 局部规则会陷入局部极小（凹形地形、U 形墙），玩家会把"卡住"记恨成 bug |
| 3 | **每个 Boids 力对应一个玩家能说出口的战术词** | 参数不能直接暴露，但必须"可解释"，否则自主性 = 失控 |
| 4 | **DBSCAN 的 eps = 通信半径 = 玩法资源** | 一个技术参数同时是算法参数与博弈参数，这是整套设计最优雅的耦合点 |
| 5 | **玩家只能对 Cluster（小队）下令，不能对单个单位下令** | 这是"消灭微操"最硬的一条规则，比任何 UI 优化都有效 |
| 6 | **必须让"分散"有收益，否则抱团是唯一的纳什均衡** | 涌现不是靠加规则，而是靠改收益结构 |
| 7 | **指挥带宽（Command Bandwidth）替代 APM 成为稀缺资源** | 把"操作量"从体力换成"决策量"，战略才成为瓶颈 |

## 1. 目标拆解：RTS 的操作量到底花在哪

先做一次诚实的拆解，才知道哪些能被自主性吃掉。

| 操作类型 | 占 APM 比重（经验值） | 本质 | 能否自动化 |
|---|---|---|---|
| 编队/框选/切换组 | 15~20% | 记忆负担 + UI 劳动 | ✅ 完全可自动化（聚类 + 稳定 ID） |
| 单位走位、拉兵、风筝 | 30~40% | 对物理引擎的实时修正 | ✅ Boids 的主场 |
| 集火/切目标 | 15~25% | 局部最优解计算 | ✅ 规则引擎 + 聚类目标选择 |
| 阵型摆放、前后排 | 10~15% | 空间结构化 | ✅ 槽位模板 + 软约束 |
| 技能释放时机 | 10~15% | 时机判断 + 预判 | ⚠️ 部分保留（见 §8.4） |
| **战略决策（去哪、打谁、何时撤）** | **<10%** | **真正的博弈** | ❌ 不该自动化，**这正是要还给玩家的** |

**设计目标**：把前四行（约 75~90%）交给算法，把重点转向最后两行。
不是"让玩家少按键盘"，而是**让玩家的每一次输入都必须是战略性的**。

## 2. 系统分层架构

```
┌─────────────────────────────────────────────────────────────┐
│ L4 玩家层   指挥带宽限制 / 教义卡组(Doctrine) / 场编辑        │  2~5 Hz 事件驱动
├─────────────────────────────────────────────────────────────┤
│ L3 意图层   命令动词 → 目标区域 + 权重组 + 承诺度 + 时限      │  事件 / 2 Hz
│             阵型模板 → 参数化槽位 (frontage, depth, arc)      │
├─────────────────────────────────────────────────────────────┤
│ L2 聚类层   DBSCAN: 己方小队识别 / 敌方兵力团 / 地形团 / 框选 │  5~10 Hz
│             → SquadID 稳定化、分裂合并事件、包围判定          │
├─────────────────────────────────────────────────────────────┤
│ L1 群体层   Boids: 分离/对齐/凝聚/槽位吸引/威胁排斥/射程保持  │  30~60 Hz
│             + 力平滑、阻尼、滞回（防抖）                      │
├─────────────────────────────────────────────────────────────┤
│ L0 导航层   流场(Flow Field) 梯度 = 全局 seek 力；局部避障     │  1~2 Hz 重算
└─────────────────────────────────────────────────────────────┘
```

**关键原则：上层只影响下层的"参数与目标"，不直接改写位置。**
任何"瞬移式"的修正都会摧毁涌现的可信度。

## 3. L0：为什么必须是流场 + Boids，而不是"纯 Boids 寻路"

这是对需求"单位寻路逻辑完全基于鸟群算法"的**工程性修正**，必须讲清楚。

### 3.1 纯局部规则的三个死穴

1. **局部极小（Local Minima）**：凹形地形、U 形墙、两建筑之间的夹角。Boids 的合力会把单位推进死点，然后在死点震荡。这是所有纯 steering 方案的经典失败模式。
2. **目标不可达 / 长距离漂移**：Boids 没有全局拓扑概念，绕大障碍时会整群贴着墙走，形成"擦墙河流"。
3. **穿过几何体**：分离力只能"事后纠正"，高速单位会插进建筑/悬崖。

### 3.2 推荐方案：把"寻路"降级为"势场"

| 层 | 内容 | 频率 | 说明 |
|---|---|---|---|
| 流场 | 在 8~16px 的粗网格上，从目标区域向外做一次 BFS/波前传播，得到每个格子的**指向上游的方向矢量** | 1~2 Hz 或目标变更时 | 支持动态障碍（建筑、火灾、封锁区），代价极低 |
| 局部避障 | 用 Context Steering / 触须(Feelers) 处理格与格之间的细节 | 30 Hz | 处理流场粒度掩盖的小障碍 |
| Boids | 分离、对齐、凝聚、威胁排斥、射程保持 | 60 Hz | 只负责"姿态"，不负责"到达" |

**对外表述**：这仍然"完全基于鸟群算法"——因为**单位的运动由群体规则决定**，流场只是提供了一条"看不见的向导梯度"（与真实鸟群的上升气流、地形风场同构）。但它把"卡住"这个体验灾难消灭了。

> 若坚持纯 Boids：必须引入**信息素/足迹场（Stigmergy）**——单位在网格上留下随时间衰减的痕迹，其他单位跟随痕迹。这能解决行军纵队与窄口拥堵，但**依然解决不了"首次探索未知目标"的局部极小**。建议：**流场做主力，信息素做香味**。信息素用于"过窄口自动列队"、"部队自然跟随开拓者"、以及"撤退时踩出亡命小径"，这是纯收益。

### 3.3 信息素（Trail）的具体设计
- 稀疏网格（只记录有值的格子），每 0.2 s 衰减 `decay = exp(-dt/τ)`，τ ≈ 3~6 s。
- 单位在 `trail` 上叠加一个核（高斯或 3×3 加权），强度与速度正相关。
- 跟随力 `w_trail * ∇trail`，仅在 `w_coh` 较高时生效，避免散兵线被吸成一条龙。
- **玩法价值**：过窄口自动纵队、增援自动沿主路汇合、被切断时"归队路径"自然形成。

## 4. L1：Boids 的 RTS 化改造

### 4.1 力的分层：用**不同的感知半径**，而不是同一个

这是 Boids 实践里最重要的技巧。三条经典规则用同一半径会让"分离"和"凝聚"打架。

| 力 | 感知半径 | 游戏语义 | 玩家可见的旋钮 |
|---|---|---|---|
| Separation 分离 | `1.2 × 单位直径` | 不重叠、不堵死、不踩踏 | **纪律 Discipline** |
| Alignment 对齐 | `3~4 × 直径` | 同向推进、齐射节奏 | **协同 Coordination** |
| Cohesion 凝聚 | `5~6 × 直径` | 不脱队、不散架 | **凝聚 Cohesion** |
| Seek 目标吸引 | 全场（流场方向） | 向意图推进 | **决心 Commitment** |
| Slot 槽位吸引 | `槽位半径 + 4 × 直径` | 阵型站位 | **阵型强度 Formation** |
| Threat 威胁排斥 | 敌方 AoE / 投射物半径 | 躲溅射、躲大招 | **谨慎 Caution** |
| RangeKeep 射程保持 | `0.8 × 射程` | 风筝、保持输出距离 | **交战距离** |
| Terrain 地形回避 | 接触前 1 帧预测 | 不撞墙 | —（不可调） |
| Trail 足迹跟随 | 4~8 格 | 行军纵队、过窄口 | **从众 Herd** |

### 4.2 运动积分（带阻尼与力上限）

```
desired = normalize( Σ wᵢ · Fᵢ )
steer   = clamp(desired · maxSpeed − v, maxForce)
v       = v + steer · dt
v       = v · (1 − drag · dt)              # drag ≈ 0.8~1.5 /s
p       = p + v · dt
```

**三个防抖要点（否则玩家会觉得"抽风"）**：
1. **力平滑**：`F_smooth = lerp(F_smooth, F_target, 1 − exp(−dt/τ))`，τ ≈ 0.12~0.2 s。
2. **滞回（Hysteresis）**：目标切换、槽位切换都要有"换边阈值"（新目标代价必须优于旧目标 20~30% 才换）。
3. **最大转向角速度**：单位不能瞬间转头，这既真实又让"承诺度"可感知。

### 4.3 权重就是行为（不设"姿态"预设）

**没有姿态枚举，只有四个可调权重。**

早期版本做过「突击 / 固守 / 袭扰 / 撤离」四组预设权重。原型实测证明这是**多余的一层抽象**：
它们没有引入任何新行为，只是把四个数字打包。玩家的真实需求分两种——

| 需求 | 直接改什么 |
|---|---|
| 队形密 / 松 | `w_sep` 与 `w_coh` 的**比值** |
| 听不听指挥 | `w_cmd`（或 ω） |

比值的实测映射（90 单位）：`w_coh / w_sep` = 1.33 / 0.54 / 0.14 / 0.06 → 最近邻间距 16.6 / 23.7 / 28.6 / 36.8，严格单调。

> **结论**：任何"战术档位"都应该是这四个数字的**快捷预设**，而不是独立的系统层。
> 预设可以有，但不该被写进模型、不该有专属逻辑分支（原型里唯一一条专属逻辑，
> 是"固守"到点后把命令力砍到 12%——删掉后行为反而更一致）。

### 4.4 领袖（Leader）机制
每个小队内选一个"事实领袖"（最靠前/血量最高/或玩家指定的单位）：
- 该单位的 `w_seek` ×2，其他单位对它额外获得 `alignment + cohesion` 加成。
- **作用**：避免"全队各自寻路"的布朗运动，自然涌现出"前锋—主体—后卫"的角色分化。
- **风险**：领袖死亡会导致队形短暂崩解——这**是好事**，是一个戏剧性事件，也是玩家该预判的"斩首"战术。

## 5. L2：DBSCAN 的四个用途与游戏语义映射

DBSCAN 不是"为了用算法而用算法"。它在这里承担的是**"从连续的运动状态中提取离散的、可被命名的结构"**这一职责。

### 用途 ①：己方小队识别（核心）

```
输入：己方单位位置（建议用 0.2s 滑动平均，防抖）
参数：eps = 通信半径（玩法参数，约 6~10 × 单位直径）
      minPts = 4~6
频率：5~10 Hz（复用 Boids 的空间哈希，O(n)）
```

**后处理（必须有，否则 UI 会闪）**：
- 与上一帧的 cluster 做 **Jaccard / 匈牙利匹配**，把 `label` 映射为稳定的 `SquadID`。
- 匹配失败的新 cluster → "新编队成型"事件；旧 cluster 消失 → "全灭/会师"事件。

### 用途 ②：DBSCAN 的三种点，恰好对应三种战场角色

这是整套设计里最漂亮的语义巧合：

| DBSCAN 概念 | 游戏语义 | 玩法后果 |
|---|---|---|
| **Core point**（核心点） | 主力、密集、火力集中 | 享受"协同加成"（相邻单位加成射速/护甲） |
| **Border point**（边界点） | 侧翼、散兵 | 视野更广、被 AoE 命中概率更低 |
| **Noise point**（噪声点） | **失联的掉队者** | 无通信共享（看不到队友视野）、不享受小队加成、可被"收拢" |

→ **`Noise` 不是一个要消灭的技术缺陷，而是游戏里的一个状态**。玩家看到"散兵游勇"图标，就知道该下 **汇合 Regroup** 命令。
→ 这也让 `eps`（通信半径）成为**玩家可争夺的资源**：被干扰、被切断、越过山脊 → eps 实际变小 → 部队自然分裂。**通信中断 = 战术事件**，无需额外系统。

### 用途 ③：敌方兵力团识别

- `eps` 取 **略大于敌方 AoE 半径**，让"抱团"被自动识别为"高价值密集目标"。
- 输出：`威胁中心`、`半径`、`兵力值`、`密度` → 喂给 `Threat 排斥力` 与 AI/提示系统。
- 衍生玩法：
  - **包围判定**：计算敌方各 cluster 相对我方 cluster 的**角度覆盖率**；覆盖率 > 240° → 标记"被包围"（士气惩罚 + UI 警报）。
  - **包抄建议**：玩家框选敌方 cluster → 自动生成环状槽位（见 §6.2）。
  - **AI 的 AoE 选点**：直接对 cluster 中心释放，AI 不需要"聪明"，聚类替它思考。

### 用途 ④：玩家框选的自动分组（交互层的杀手锏）

- 玩家拖一个大框选中 40 个单位 → **DBSCAN 自动分成 3 个簇** → UI 显示 3 个小队徽章，每个自带拖拽手柄。
- 玩家把 3 个徽章拖到 3 个方向 = **3 次拖拽**。传统 RTS 需要 3 次框选 + 3 次右键 + 若干次修正。
- **这是"降低操作量"最直接的交互收益**，也是本作最有辨识度的操作手感。

### 用途 ⑤：地形/障碍物聚类（静态，开局一次）

- 对障碍物图元聚类 → 识别"大型地物团块" → 产出战术点（伏击区、掩体、可绕行侧翼）。
- **连通区域分割用 Flood Fill 更合适**，不要硬套 DBSCAN——诚实的工程判断。
- 通道（Chokepoint）识别建议用**距离变换的脊线**或"两个障碍簇之间的最窄缝隙"，而非密度聚类。

### 参数与性能

| 项 | 建议 |
|---|---|
| 加速 | 复用 Boids 的 Uniform Grid，DBSCAN 在网格上做邻域查询，近似 O(n) |
| 频率 | 5 Hz（1000 单位在现代 CPU 上 < 1 ms） |
| 稳定性 | 位置先做 0.2 s 滑动平均；cluster 结果做 1~2 帧的多数表决 |
| 变密度 | 固定 `eps` 会漏掉 3 人小队。方案：先固定 eps 跑一次，对 `size < minPts` 的簇用 `1.5×eps` 再聚一次（两次 DBSCAN，比 HDBSCAN 更好调、更可预测） |
| 可预测性 | **优先于最优性**。eps/minPts 作为固定玩法常数，并在 UI 上可视化（画一个半透明的"通信圈"） |

### 5.5 身份稳定性：DBSCAN 是无状态的，Squad 必须有状态 ★

**问题**：DBSCAN 每次调用都从零开始；输出的 `label` 整数无意义，成员集合随位置抖动而翻转。
若把 `label` 直接当身份，会出现：单位一帧内"叛逃"到邻队、小队徽章闪烁、协同加成时有时无、
部队被切断时整队指令凭空失效。

**结论：把"观测"与"身份"彻底分离。**

|            | **Cluster（簇）** | **Squad（小队）** |
| ---------- | -------------- | ------------- |
| 是什么        | 单帧的**观测**      | 跨帧的**状态**     |
| 生命周期       | 一帧             | 直到死亡/解散       |
| 由谁产生       | DBSCAN         | 追踪器 + 滞回      |
| 权威性        | 只是证据           | 唯一真相          |
| 玩家可见       | 否（可视化可选）       | 是（徽章、数字键）     |
| 参与**控制**回路 | **绝不**         | 是（且只通过权重/意图）  |
| 参与**认知**回路 | 是              | 是             |

一句话：**DBSCAN 是传感器，不是实体的定义者。**

#### 5.5.1 不稳定的五个来源，分而治之

| 来源 | 现象 | 对策 |
|---|---|---|
| label 编号任意 | 同一集合每次编号不同 | 用集合匹配（Jaccard）生成 ID，**永不使用 DBSCAN 的 label 整数** |
| eps 边界往返 | 单位在 eps 边缘抖动 | 软隶属 + 滞回阈值 |
| minPts 翻转 | 进出 1 个单位导致簇合法性翻转 | **锚点法**（core 持久化） |
| 真实移动 | 部队确实分开了 | **不要修**，这是正确的观测 |
| 变密度 | 3 人小队被大簇吃掉 | 二次聚类；锚点法天然缓解 |

#### 5.5.2 锚点法（Anchor-based Identity）★ 推荐实现

**核心思想：身份锚定在"核心"上，而不是锚定在整个成员集合上。**

1. 每帧 DBSCAN 之后，取每个簇的 **core points**（ε 邻域内 ≥ minPts 的点）。
2. 把 core points 与上一帧的 **Anchors**（小队锚点）做匹配（匈牙利，代价 = 距离）。
3. 匹配成功 → 锚点平滑移动；匹配失败超过 0.6 s → **锚点死亡**（小队解散）。
4. 出现**远离所有锚点**的密集子集，且持续 3 帧 → **孕育新锚点**（小队诞生）。
5. 每个单位每帧结算到各锚点的**软隶属度**：

```
aᵤ,ₛ ← (1−α)·aᵤ,ₛ + α·exp(−d(u, anchorₛ)² / 2σ²)      # α ≈ 0.15，5~10 Hz
```

6. 单位的实际归属 = `argmax a`，且**只有当 `a_new − a_old > 0.25` 且持续 0.3 s 才切换**。

这样，**DBSCAN 只负责"提名锚点"，身份由锚点的连续性保证。**
锚点数量是 O(小队数) 而非 O(单位数)，匹配代价可忽略。

> **附带收益**：锚点天然就是"事实领袖"（§4.4）。领袖阵亡 = 锚点消失 = 小队重组，语义完全自洽。

#### 5.5.3 分裂 / 合并的事件语义

DBSCAN 的无状态性在**分裂与合并**上不是缺陷，而是玩法。

| 事件         | 判定                                   | 语义与规则                                         |
| ---------- | ------------------------------------ | --------------------------------------------- |
| **分裂 1→2** | 一簇匹配到 2 个锚点，或一个锚点的成员被山脊/窄口切成两块超过 1 s | 被切断。**两个子队都继承原意图**；较小一方标记"孤军"（失去通信加成，但保留撤退自由） |
| **合并 2→1** | 两簇成员交集 > 30%，或两锚点距离 < 1.5σ 持续 1 s    | 会师。继承**较强一方**的意图（兵力/士气），另一方降级为"跟随"            |
| **诞生**     | 新密集子集持续 3 帧                          | 增援抵达 / 残兵聚拢 → 新 Squad，继承最近锚点的姿态               |
| **死亡**     | 锚点 0.6 s 无匹配，或成员全灭                   | 解散，其"残存指令"立即失效                                |

**关键设计**：必须存在 `残存指令`（orphan intent）——被切断的小队不能因为"没人给它下令"就原地发呆。

#### 5.5.4 两个致命反馈陷阱

**陷阱 A：结构固化（Structural Freezing）**

若 Squad 因为"我是小队"而提高凝聚权重 → 单位抱得更紧 → DBSCAN 看到更紧凑的簇 → 还是这个小队 → 凝聚权重继续维持。
**涌现被自己的观测锁死**，部队变成一个永远不会分裂的球。

> **铁律 1：Squad 的身份不能反过来调节它自己的成员构成。**
> 所有 Boids 权重必须来自 `Stance × Doctrine`，**绝不来自"维持小队完整"这个目标**。
> 同理，DBSCAN 参数绝不能被"小队健康度"调节。

**陷阱 B：效应阶跃（Effect Step）**

若"协同加成"直接绑定 label，则 1 帧的 label 翻转 = 1 帧加成消失 = 数值抖动、手感抽搐。

> **铁律 2：任何由离散标签驱动的数值效果，都必须有 0.3~0.8 s 的斜坡与独立的滤波状态。**
> `bonus ← lerp(bonus, target, 1 − exp(−dt/τ))`，τ ≈ 0.4 s。
> 这样 100 ms 的身份抖动在数值上完全不可见。

#### 5.5.5 回路隔离：DBSCAN 必须留在认知回路里

| 回路 | 频率 | 内容 |
|---|---|---|
| **控制回路** | 60 Hz | 单位力 → 位置。**完全不经过 DBSCAN** |
| **认知回路** | 5~10 Hz | 位置 → DBSCAN → 锚点匹配 → 隶属度 → UI / AI / 慢变量（士气、补给） |

**DBSCAN 的 200 ms 延迟只出现在认知回路，玩家感知不到；一旦它进入控制回路，就会变成可见的迟滞与抖动。**

#### 5.5.6 验收不变量（可直接写成单元测试）

| 测试 | 判据 |
|---|---|
| label 抖动率 | 稳定行军时，单帧归属翻转的单位比例 **< 1%** |
| SquadID 寿命 | 平均 **> 30 s**（非战斗状态） |
| 位置噪声鲁棒性 | 全员位置加 ±5% 随机抖动，SquadID 保持率 **> 95%** |
| 小队数稳定性 | 1000 单位自由移动 60 s，小队数波动 **< ±2** |
| 分裂/合并频率 | 每分钟 **0.5~2 次**，而非每帧 |
| 效果连续性 | 任意单帧 label 翻转，单位属性变化 **< 2%** |

## 6. L3：意图层 — 命令语法与阵型

### 6.1 命令动词：只保留 6 个，全部是"意图"

| 动词 | 输入 | 内部展开 | 玩家心智 |
|---|---|---|---|
| **进军 Advance** | 区域 / 一条推进线 / 方向 | 生成 seek 目标点序列 + 阵型参数 | 往那边压 |
| **固守 Hold** | 区域 | 生成防御槽位环/线，slot 权重拉满 | 守住这里 |
| **交战 Engage** | 敌方 cluster 或区域 | 进入交战半径后交给 Boids + ROE | 打他 |
| **撤离 Withdraw** | 方向 / 集结点 | 提高 `w_sep`、降低 `w_coh`、命令力拉满 | 跑 |
| **袭扰 Harass** | 区域 | 拉高 `rangeKeep`，禁止近战 | 遛他 |
| **汇合 Regroup** | 点 | 短时提高 `w_coh` + 降低 `w_sep`，收拢 Noise 点 | 集合 |

**每个命令隐含三个参数（玩家不用调，来自 Doctrine）**：
- `Weights` 权重组（`w_sep / w_ali / w_coh / w_cmd`，即命令自带的权重快照）
- `Commitment` 承诺度（0~1）：单位在多长时间内不会因为新威胁而偏离目标 → **可预测性的来源**
- `TTL` 时限：命令自动过期 → 防止"部队永远停在上一道命令里"

> **承诺度是本作"可读性"的关键**：玩家能预判"我下了进军命令，他们 8 秒内不会因为看到对面 3 个兵就掉头"。没有承诺度的自主行为，玩家学不会。

### 6.2 阵型：参数化槽位 + 软约束

**不要用固定偏移的硬阵型**（那是传统 RTS 的失败点：地形一窄就崩）。

```
阵型 = f(锚点 anchor, 朝向 heading, 前沿宽度 frontage,
        纵深 depth, 弧度 arc, 间距 spacing, 层数 ranks)
```

- **线阵**：`arc = 0`
- **楔形**：`frontage` 小、`ranks` 多、按 V 型排布
- **环形包围**：以敌方 cluster 中心为锚点，`arc = 2π`，槽位按兵力加权均分角度
- **散兵线**：`spacing` 大、`ranks = 1`
- **纵队**：`frontage = 1 单位`、`ranks = n`（过窄口自动切换）

**槽位分配**：贪心 + 距离排序，或匈牙利算法，**每 0.5 s 一次**，并加滞回：
> 单位只有当"新槽位的代价 < 当前槽位代价 × 0.75"时才换槽。

**软约束实现**：
```
F_slot = clamp( w_slot · (slotPos − p), maxSlotForce )
```
- 槽位力有上限 → 单位遇到障碍会**自然绕过**而不是"卡在槽位上"。
- 槽位不是"必须到达的格子"，而是"一个偏好方向"。这是与经典 RTS 阵型的本质区别。

**阵型流动性（Formation Fluidity）**——本作对阵型痛点的正面回答：

| 场景 | 自动响应 |
|---|---|
| 窄口（宽度 < frontage） | `frontage → 1`，切纵队，`w_trail ↑`，`w_slot ↓` |
| 开阔地 | 恢复原阵型，`w_slot ↑` |
| 遭遇 AoE 威胁 | `spacing ↑`（自动散开），`w_coh ↓` |
| 背后被包抄 | `arc` 转向，自动形成半环 |
| 侧翼有敌人 | 局部 `heading` 偏转（不是整队转向）→ 形成"斜线接触" |

### 6.3 编队的三层对象模型

```
Squad   (DBSCAN 涌现，系统所有，玩家可命名、可绑定数字键)
  └ Group (玩家显式编组，数字键 1~9，可跨 Squad)
      └ Formation (阵型参数 + 权重组 + 意图，由 Group 或 Squad 持有)
```

- **Squad 是"事实"，Group 是"意志"**。玩家操作 Group；Group 的命令会下发到它覆盖的 Squad；Squad 内部用 Boids 自行解决站位。
- **好处**：Squad 可以被切断、被合并、被打散，而玩家的 Group 定义不会瞬间失效 → 系统表现"有韧性"。

> 复杂任务的正解是「权重组 ×2（默认 / 接敌）+ 区域 + 一个脱离阈值」，分支由

### 6.4 复杂任务（已废弃，见 §14.3 ★）

§6.1 的 6 个动词只描述**如何开始**，没有回答**开始之后遇到什么该怎么办**。
"驻守这片区域"如果只等于"把 unit.seek 指向区域中心"，那它就不是一个任务，只是一个坐标。
真正的任务是 **policy（策略）而不是 command（命令）**：

> 命令是时间轴上的一个点；任务是带分支与终止条件的轨迹。

#### 6.4.1 任务四元组（Task = Space × Contract × Authority × Budget）

```
Task {
  space:    AreaExpr        # Circle | Polygon | Band(带) | Line | Point + 取向
  contract: ClauseSet       # 条件 → 动作 规则表（默认预填）
  auth:     L1 | L2 | L3    # 授权等级：它自己可以决定到哪一步
  budget:   { ttl, lossCap }# 时限与可承受损失，超限自动请示/中止
  phase:    [Phase...]?     # 阶段链：复杂任务 = 意图链
}
```

**玩家的操作介质**：选模板 → 画区域 → 调 2~3 个滑杆。
**绝不要求玩家写规则**（见 §6.4.3 的"三旋钮原则"）。

#### 6.4.2 空间层：从 AreaExpr 到槽位

通用五步：

```
区域 → 候选点采样 → 价值评分 → 兵力分组 → 参数化阵型生成槽位(§6.2)
```

- **候选采样**：泊松盘采样（均匀、可控密度）或加权 Voronoi（按价值）。
- **价值函数** `V(p) = w₁·视野覆盖 + w₂·通道控制 + w₃·掩体 + w₄·退路可达性`。
  其中"通道控制"直接复用 DBSCAN 的敌方聚类与地形脊线分析（§5 用途③⑤）。
- **兵力分组**：永远分三组，这是"驻守"与"推进"共用的骨架。

| 组 | 比例 | 位置 | 姿态 | 职责 |
|---|---|---|---|---|
| **前哨 Picket** | 10~15% | 外侧通视点，`spacing` 大 | Harass | 见敌即报、接触即退，**不硬拼** |
| **主阵地 Main** | 55~65% | 支撑点，面向威胁方向成弧 | Hold | 承受冲击 |
| **预备队 Reserve** | 20~30% | 背向威胁一侧，距主阵地 0.5R | Assault | 反击 / 补缺口 / 掩护撤退 |

#### 6.4.3 契约层：5 类条件 × 4 类动作

| 条件类型 | 判据（全部带滞回） | 典型阈值 |
|---|---|---|
| **敌情** | 敌方聚类兵力 / 我方兵力（复用 DBSCAN 战力量化） | 0.3 / 0.7 / 1.2 |
| **接近** | 敌方聚类到我方锚点的距离 / 我方射程 | 3.0 / 1.5 / 1.0 |
| **损失** | 累计伤亡 / 初始兵力 | 15% / 25% / 40% |
| **空间** | 被包围角覆盖率、退路是否被切断 | 180° / 240° |
| **通信/时间** | 是否在线（eps 内）、任务计时、支援是否抵达 | — |

| 动作 | 含义 |
|---|---|
| **ShiftStance** | 切姿态（唯一允许改 Boids 权重的方式） |
| **ShiftAnchor** | 换阵位（收缩 / 前推 / 转侧翼 / 退到备选点） |
| **Concentrate / Disperse** | 改 `spacing` 与协同上限的投入 |
| **Report / Request** | 上报 or **请示**（见 §6.4.4） |

**三旋钮原则**：玩家只调三个滑杆，其余由模板预填。

| 滑杆 | 范围 | 影响 |
|---|---|---|
| **激进度** | 保守 ↔ 激进 | 接触即退的阈值、追击距离、预留队投入时机 |
| **脱离阈值** | 早 ↔ 晚 | `lossCap`、`被包围角` 容忍度 |
| **追击距离** | 0 ↔ 2×射程 | 是否允许脱离阵位追杀（0 = 绝不脱阵） |

> 这三个滑杆能表达的战术差异，覆盖 90% 的场景。**剩下的 10% 交给教义卡（§7.2），不要交给契约编辑器。**

#### 6.4.4 授权层与请示制（Approval）★★ 本设计最关键的一块

**玩家不做操作，玩家做审批。**

| 等级 | 可以自主决定 | 必须请示 | 适用 |
|---|---|---|---|
| **L1 执行** | 站位微调、Boids 自保 | **一切**（改目标、撤退、追击） | 新手、关键节点 |
| **L2 调整** | 姿态、阵型、阵位、脱离危险 | 改目标、追击超出预算 | 默认 |
| **L3 裁量** | 追击、转攻、弃守、按自己判断改目标 | 只在超过 `lossCap` 时 | 老练部队、追击战 |

**请示机制（关键）**：

- 满足契约中的 `Request` 条件时，小队向玩家发出**一条待批准请求**，附上归因（见 §6.4.6）与两个选项。
- 玩家 **1 键批准 / 1 键否决**，各消耗 0.5 格指挥带宽（§7.1）。
- **超时未答**：按授权等级的默认策略执行（L1 = 保持不动，L3 = 自主行动）。

**为什么这是本作的核心操作**：

1. 玩家从"操作员"变成"指挥官"——注意力只花在**真正需要战略判断**的时刻。
2. 高分玩家的差异从"手速"变成"**授权得准不准**"：L3 的部队能抓住战机，也可能追过头被打伏击。
3. **授权本身是一场赌博**，这天然产生叙事与复盘空间。
4. 系统不会沉默地替你决定，也不会事无巨细地烦你——请求只在契约命中时出现。

> 建议：单位有 `老兵度`，影响 **L3 的判断质量**（越老练，自主决策的错误率越低）。
> 这让"练级"有了新的意义，也让"精锐小队"成为可追求的战术资产。

#### 6.4.5 阶段链与抢占

**复杂任务 = 意图链。** 阶段推进由契约驱动，不需要玩家逐段点击。

```
推进带 → 等距切段(k ≈ 带长 / 1.5×射程) → 每段一个 Phase
Phase: 推进(Assault) → 接触(Hold, 短暂) → 巩固(Hold + 前出侦察) → 下一段
```

- **自动推进条件**：接触强度 < 30% 且无损失超限 → 自动进入下一段。
- **抢占（Preemption）**：高优先级任务（紧急撤离、被包抄）可打断当前任务；**用栈保存未完成状态**，脱险后自动恢复（`interrupt stack`）。
- **任务冲突**：两个任务要求同一 Squad → 按优先级裁决，并把被夺权的一方**显式降级为"支援"**（不能默默无视，否则玩家会觉得指令丢了）。

#### 6.4.6 归因 UI：回答"它为什么撤了"

可解释性有两个层次，v0.1 只做了第一层：

| 层次 | 问题 | UI |
|---|---|---|
| L1 | 它现在在做什么 | 意图图标 + TTL 环 |
| **L2** | **它为什么改变了主意** | **归因气泡**："损失 28% > 阈值 25%" / "被包围 240°" |

每次 `ShiftStance` / `ShiftAnchor` 都生成一条**一句话归因**，保留最近 3 条。
**没有这一层，玩家会觉得部队"突然不听话了"。**

#### 6.4.7 验收

| 测试 | 判据 |
|---|---|
| 任务下达操作量 | 驻守 / 推进 均 **≤ 3 次输入** |
| 任务自动完成率 | 无干扰场景下，阶段链 100% 自动推进，0 次额外操作 |
| 请示频率 | **每分钟 1~3 次**（不是 10 次，也不是 0 次） |
| 归因覆盖率 | 每次姿态/阵位切换都有归因记录，**100%** |
| 抢占恢复正确率 | 中断任务恢复后目标位置误差 **< 1 个阵位** |

## 7. L4：玩家层 — 把稀缺资源从"手速"换成"决策"

### 7.1 指挥带宽（Command Bandwidth）★核心机制

> **同时能维持的"活跃意图"数量有限**，例如 `3 + 已占领节点数`。

- 每个活跃**任务**占用 1 格带宽，持续到完成/过期/撤销。**阶段链不额外收费**（否则玩家不敢用复杂任务）。
- 每次**批准/否决请示**消耗 0.5 格（§6.4.4）——逼玩家二选一，而不是"全都批"。
- 带宽用尽时，新命令会**替换**最旧的意图（或需要先撤销）。
- **效果**：
  - 玩家不能"什么都做"，必须取舍 → **这就是战略**。
  - 高分玩家的差异体现在"把 3 格带宽用在哪"，而不是"每秒点几下"。
  - UI 只需 3 个槽位 → **极简界面成为可能**。

这条机制把"减少微操"从"技术上做不到"变成"规则上不需要"。

### 7.2 教义（Doctrine）：玩家编辑规则，而不是编辑单位

玩家在战前/战中编辑的是**行为规则卡**，例如：

| 教义卡 | 效果 | 代价 |
|---|---|---|
| 集火最弱 | 切目标时优先残血 | 可能浪费火力在坦克上 |
| 保持距离 | `rangeKeep` ×1.5 | 输出时间下降 |
| 保护后排 | 前排对后排位置有强 cohesion | 前排机动性下降 |
| 侧翼偏好 | 自动向敌方 cluster 侧后方偏移 | 容易被正面击穿 |
| 死战不退 | 士气下限提高，`w_seek` 不衰减 | 无法自动撤退，全灭风险 |

**3~5 张卡槽 + 组合效果** → 这是本作的"构筑深度"，替代了传统 RTS 的"操作深度"。

### 7.3 场编辑（Field Editing）：间接控制的最高形态

玩家可以在战场上放置**影响场**（有资源成本、有冷却）：

- **压力区（Attractor）**：范围内的己方单位 seek 权重提升——"往这里压"。
- **禁区（Repulsor）**：单位回避——"别走这条道"。
- **集结点**：短期凝聚力提升。
- **视野/侦察标记**：吸引侦察单位。

> 设计传承：这是《黑与白》《地下城守护者》《Majesty》的"间接控制"脉络——
> 玩家提供**激励与地形**，单位自己决定怎么活。区别在于本作把它做成了 RTS 的战术层。

### 7.4 保留极少量"高价值微操"（不要做成 0 操作）

- **主动技能**：长冷却、改变战局（如"冲锋"、"烟雾"、"齐射"）。
- **紧急指令**：只能对单个 Squad 用，冷却长，效果强（"立刻脱离"）。
- **目的**：给高手留出**表达空间**，但收益递减到**不改变战略结果**。
  > 原则：手速能赢一次交战，赢不了一场战争。

## 8. 交互规范（具体到操作手势）

### 8.1 输入三层

| 层 | 频率 | 输入方式 | 例子 |
|---|---|---|---|
| 战略层 | 每 30~120 s | 面板 / 卡组 | 换教义、造兵、选节点 |
| 战役层 | 每 10~30 s | 拖拽 / 画线 / 放场 | 推进线、防线、压力区 |
| 紧急层 | 每 2~5 s | 单键 + 点选 | 紧急脱离、主动技能 |

### 8.2 具体操作清单

| 手势 | 结果 | 替代了什么 |
|---|---|---|
| **拖拽一个圆** | 选中范围内的己方单位（自动 DBSCAN 分组） | 框选 |
| **右键点击空地的某方向** | 智能判定：进军 / 固守（按距离与权重） | 移动 + 摆阵 |
| **右键点击敌方 cluster** | 交战意图（目标为整个 cluster，不是单个单位） | 集火点击 + 修正 |
| **在屏幕上画一条线** | 生成"战线槽位"（沿线等距采样 → 槽位） | 逐个摆位 |
| **双击 squad 徽章** | 展开 squad 的"意图面板"（看它在想什么） | —（**可解释性**） |
| **按住并拖拽 squad 徽章到某区域** | 给整队下达意图 | 框选 + 右键 |
| **滚轮（在选中状态）** | 调 `spacing`（紧凑 ↔ 散开） | 拉兵散开 |
| **空格** | 战术暂停 / 慢放（单机） | —（给思考留时间） |
| **数字键 1~9** | 选中 Group | 编队 |

### 8.3 可解释性 UI（自主性游戏的生死线）

玩家必须能回答"我的兵为什么往那跑"。三件套：

1. **意图图标**：每个 squad 头顶一个图标（进军/交战/撤离），带计时环（TTL）。
2. **力场可视化（克制版）**：选中 squad 时，用低透明度箭头显示 `seek`、`threat`、`slot` 三个主力的方向。不要显示全部 9 个力。
3. **预测轨迹**：按住某个 squad 时，画出 1~2 s 后的预计位置带（考虑承诺度）。
4. **状态徽章**：`凝聚度 / 通信状态 / 包围警报 / 散兵数`。

> **反模式**：让玩家去读参数、读波形图。玩家只看得懂"箭头方向和图标"。

### 8.4 学习曲线设计（渐进披露）

| 阶段 | 玩家能做什么 | 隐藏什么 |
|---|---|---|
| 教学 1 | 只下达 3 个命令（进军/固守/交战） | 阵型参数、DBSCAN 概念全部隐藏 |
| 教学 2 | 引入权重滑杆（4 个） | 权重表仍隐藏，用"性格描述"包装 |
| 中期 | 引入指挥带宽限制、教义卡 | — |
| 后期 | 场编辑、阵型参数微调 | — |

## 9. 让涌现"好看"：用收益结构引导，而不是用规则禁止

**这是整个设计最容易被做错的地方。**

在普通 RTS 里，"抱团（blob）"是纳什均衡：火力集中 > 火力分散。如果什么都不改，Boids 的凝聚项会把所有单位吸成一个球，涌现退化。

**正确做法：改收益结构，让"分散"在数学上划算。**

| 机制 | 效果 | 涌现后果 |
|---|---|---|
| **AoE 对密度敏感**（伤害 ∝ 局部单位数²） | 密集 = 自杀 | 单位自动散开，不需要"散开"按钮 |
| **侧翼/背击伤害加成**（+30~50%） | 包抄 = 收益 | Boids 的 threat/seek 权重自然产生绕行 |
| **协同加成有上限**（相邻 3 个即满） | 第 4 个邻居无收益 | 自然形成"小群"而非"大球" |
| **视野/侦察熵**（分散单位提供更多情报） | 分散 = 信息优势 | 散兵线成为有效战术 |
| **补给线/通信半径** | 离队 = 失去加成 | 分兵有代价，不是无脑散开 |
| **地形伤害/阻滞** | 狭窄地形惩罚密集 | "窄口"天然是战术点 |

> **设计原则：不要禁止坏形态，要让坏形态自然被惩罚。** 玩家会自己学会散开，而且会觉得"是我发现的战术"，而不是"游戏让我这么干"。

## 10. 性能预算（1000 单位 @ 60 fps）

| 系统 | 频率 | 单位耗时 | 说明 |
|---|---|---|---|
| Boids 邻域查询 | 60 Hz | 用 Uniform Grid，每格 2×sep 边长，查询 9 格 | ~0.3 ms |
| 力计算 + 积分 | 60 Hz | 9 个力 × 1000 | ~1.5 ms |
| 局部避障（触须） | 30 Hz | 复用网格 | ~0.4 ms |
| 流场重算 | 1~2 Hz | 256×256 BFS | ~2 ms（分摊） |
| DBSCAN | 5 Hz | 网格加速 | ~0.5 ms |
| 槽位分配 | 2 Hz | 贪心 + 滞回 | ~0.2 ms |
| 渲染/动画 | 60 Hz | Instanced | — |

**总计 ~3 ms 逻辑**，留出大量预算给渲染与 AI。**单元测试要点**：1000 单位过 1 格宽窄口，不出现抖动/穿模/永久堵塞。

## 11. 原型路线与验证指标

### 11.1 五个里程碑（每个都可独立验证）

| 阶段 | 内容 | 验证点 |
|---|---|---|
| **M1** | 流场 + Boids + 一组权重 | 不卡、不抖、不穿模；1000 单位过窄口 |
| **M2** | DBSCAN 小队识别 + 稳定 ID + 徽章 UI | 徽章不闪；分裂/合并事件正确 |
| **M3** | 6 个命令动词 + 参数化槽位阵型 | 玩家能用 3 次操作指挥 40 个单位 |
| **M4** | 指挥带宽 + 教义卡 | 玩家开始"舍不得"用带宽 → 取舍出现 |
| **M5** | 反 blob 数值 + 平衡 | 抱团率下降，散开成为主流 |

### 11.2 可量化的验收指标 ★

| 指标 | 定义 | 目标 |
|---|---|---|
| **APM–胜率相关性** | 玩家 APM 与胜率的皮尔逊相关 | **< 0.3**（传统 RTS 约 0.5~0.7） |
| **每场指令数** | 有效命令事件数 | 比同类 RTS 下降 **一个数量级** |
| **有效输出时间比** | 单位处于射程内的时间 / 存活时间 | **> 70%**（传统 RTS 手动操作约 40~50%） |
| **过窄口耗时** | 20 单位通过 1 格宽通道 | **< 3 s**，且无单位卡死 |
| **形态分散度** | 平均最近邻距离 / 单位直径 | 稳定在 1.5~2.5（不 blob 也不散架） |
| **失控感评分** | 玩家问卷："我能预测我的部队吗" | **> 4/5** |
| **指令–结果延迟** | 下达命令到肉眼可见变化的时间 | **< 1.5 s**（超过就是"没反应"） |

> 建议把"APM 与胜率弱相关"作为**核心北极星指标**。如果它不下降，说明自主性没有真正吃掉操作量。

## 12. 反模式清单（踩了会毁掉设计）

| 反模式 | 后果 | 修正 |
|---|---|---|
| 纯 Boids 做长距离寻路 | 单位卡在墙角，玩家骂 bug | 流场兜底 |

| 单位完全不可控 | 代理感丧失，玩家觉得"游戏在替我玩" | 保留紧急指令、场编辑 |
| 没有可视化 | 自主性 = 黑箱 = 失控 | 意图图标 + 力场箭头 |
| 不做反 blob 数值 | 涌现退化为"大球推进" | §9 |
| 命令瞬间生效（无转向时间） | 无重量感、不可预判 | 加速度/转向角速度限制 |
| 阵型用固定绝对偏移 | 一遇地形就崩 | 参数化 + 软约束 |
| 有承诺度但不告诉玩家 | 玩家以为单位"不听话" | UI 显示承诺计时环 |

# 14. 算法选型（已抽取为独立文档）

> ### 📄 本节已独立成篇 → **[`behavior-algorithms.md`](behavior-algorithms.md)**
>
> 该文档自足、可单独使用，包含：三层算法目录（支撑层 S / 群体层 A / 小队层 B）、
> 关键伪代码、参数初始值、成本表、12 条陷阱总表、选型速查、完整参考文献。
> **以该文档为准**。以下 §14.1–§14.5 为早期存档，仅作设计过程记录，不再维护。

> **总原则：复杂度沉到局部规则里，不要浮到系统层。**
> 规则越简单，行为越可信；系统越简单，涌现越不会被自己的机制压死。
> 上一版把复杂度放在"任务/契约/授权"层——正确的位置是**每个单位的每帧**。

## 14.1 群体层（Swarm / Flocking）

### 必选四件套

| #   | 算法                                         | 一句话原理                      | 替代玩家什么操作      | 成本  |
| --- | ------------------------------------------ | -------------------------- | ------------- | --- |
| S1  | **Boids**（Reynolds 1987）                   | 分离 / 对齐 / 凝聚三力加权           | 个体走位、拉兵       | 低   |
| S2  | **k-近邻拓扑交互**（Ballerini 2008，椋鸟）            | 用「最近 6~7 个邻居」代替固定半径        | ——            | 极低  |
| S3  | **Couzin 三区 + 少数知情个体**（2002 / 2005）        | 排斥区 / 定向区 / 吸引区；只让少数单位知道方向 | **框选全体 + 右键** | 低   |
| S4  | **ORCA / RVO 无碰撞**（van den Berg 2008/2011） | 速度障碍 + 半平面线性规划             | 反复微调防堵、防穿模    | 中   |

### 为什么 S2 是性价比最高的一条

固定半径邻域有两个死穴：**密集处邻居爆炸**（O(n²) 退化、行为僵硬）、**稀疏处没有邻居**（掉队的单位失去全部社交力）。
真实椋鸟群用的是**拓扑距离**（最近 6~7 个同伴），与群体密度无关。
→ 换成 k-NN 后，阵型在密集/稀疏两种情况下**行为一致**，掉队单位也仍受牵引。**改动量极小，收益极大。**

### S3 是本作"低操作量"的算法核心

Couzin 模型证明：**只要少数个体知道目标方向，整个群体会被引导过去**，且知情者比例低到 5~10% 仍有效。
→ 映射到游戏：玩家只需要给 **1~2 个"知情者"** 下指令（队长、或任意被标记的单位），其余单位靠定向区自己跟随。
→ 这**天然替代了"框选 40 个单位 + 右键"**，而且比一键全体移动更自然（有传播延迟、有队形）。

### 可选 / 特定场景

| 算法 | 适用 | 不适用 |
|---|---|---|
| **Vicsek**（1995） | 极简同向，最便宜的"协同" | 需要队形时不行 |
| **Cucker–Smale**（2007） | 平滑无抖的行军，有收敛保证 | 需要快速响应时太"软" |
| **Social Force**（Helbing 1995） | 溃败、挤窄口的真实混乱感 | 正常行军太"黏" |
| **Continuum Crowds**（Treuille 2006） | 千单位大兵团的流体感 | 丢失个体性，不适合英雄单位 |
| **Stigmergy 信息素** | 过窄口自动纵队、增援自动汇合 | 需要额外一张场，调参麻烦 |

### ⛔ 明确劝退：群体智能"优化器"

PSO、ACO、GA、人工蜂群、萤火虫、灰狼、神经进化、人工免疫——
**它们是离线优化器，不是实时控制器**：需要"迭代到收敛"，而 RTS 每帧只有 16 ms 且环境持续变化。
放进实时回路的结果必然是：抖动、不可预测、不可调试、无法向玩家解释。

**正确用途**：

| 用途 | 说明 |
|---|---|
| 离线调参 | Boids 九力权重、阵型参数、契约阈值的批量搜索 |
| 战前生成 | 关卡编队模板、AI 参数、兵种数值的进化搜索 |
| 自动对局 | 平衡性回归测试，用 GA 探索策略空间 |
| **低频分配（唯一例外）** | 蚁群 / 拍卖 / 匈牙利用于**目标分配**（1 Hz、n 小、允许 100 ms）是合理的 |

## 14.2 小队层（Artificial Life Behaviors）

### 推荐六件套

| # | 算法 | 一句话原理 | 涌现出什么 | 成本 |
|---|---|---|---|---|
| Q1 | **Response Threshold 阈值响应**（Bonabeau / Theraulaz） | 每个单位对每类任务有一个阈值；局部刺激超过阈值就切换角色 | **角色分化**（前排/输出/预备队）完全去中心化 | 极低 |
| Q2 | **Utility AI 打分** | 每个候选行为算一个分，取最高 | 小队级决策（打/退/守/绕） | 低 |
| Q3 | **Subsumption 包容架构**（Brooks 1986） | 分层行为，低层可抑制高层 | 个体本能：保命 > 守位 > 追击 | 极低 |
| Q4 | **Quorum 阈值共识** | 达到临界数量的个体同意才触发集体行动 | **士气崩溃 / 集体冲锋** | 低 |
| Q5 | **Voronoi / 加权 Voronoi 分区** | 按小队位置与兵力自动切分空间 | 防区自动分配 | 低 |
| Q6 | **拍卖 / Contract Net**（Smith 1980） | 目标挂牌，各单位竞价 | 目标分配（谁打谁） | 低 |

### Q1 是最值得先做的

```
若 (局部受伤速率 > θ_前排) 且 当前非前排  →  切到前排
若 (最近敌人距离 > θ_预备)                →  切到预备队
若 (附近队友密度 < θ_孤立)                →  提高 cohesion
```

- **零中央分配、零全局计算**，每个单位只读自己的局部感知。
- 阈值可随**老兵度 / 士气 / 兵种**调制 → 精锐部队自然承担更危险的职责。
- 结果：阵型里的前排后排**不是玩家摆的，是长出来的**。

### Q2 用来做"小队的一个决定"，而不是"单位的很多决定"

小队层每 0.5 s 打一次分：

```
score(进攻) = 兵力优势 × 激进度 − 损失率
score(固守) = 阵地价值 × 守备加成
score(后撤) = 损失率 × (1 − 士气) + 被包围程度
score(绕行) = 侧翼价值 × 机动余量
```

只有 4~6 项，**可解释**（UI 能显示"因为损失 31% > 30%，选了后撤"），**可调**（每项系数就是难度旋钮）。

### Q3 是"个体不犯傻"的保险

优先级由低到高（高层抑制低层）：追击目标 < 保持阵位 < 避免碰撞 < 脱离致命威胁。
Brooks 的架构在多智能体上极其鲁棒，而且**天然可解释**——下层一直在跑，只是被抑制。

### Q4 把"士气"从数值变成涌现事件

不是"士气值 < 30 就溃退"，而是：**每个单位独立判断"我该跑了"，当逃跑者比例超过 quorum，整队崩溃**。
→ 溃退变成一个有前兆、有传播、可能被"督战"阻止的**过程**，而不是一个开关。

### 可选 / 加分项

| 算法 | 用途 |
|---|---|
| **Predator-induced flocking**（Couzin） | 受攻击时群体自然分裂出"躲避真空区"→ 自动走位，无需拉扯 |
| **需求驱动 Agent**（饥饿 / 弹药 / 疲劳） | 行为由需求涌现：自动回补给、自动抢资源点 |
| **Delaunay 邻接** | 邻域关系、"谁该支援谁" |
| **双稳态 + 滞回** | 进攻 ↔ 溃退之间的跳变，防止边界抖动 |

## 14.3 于是"复杂任务"塌缩成三个旋钮 ★

上一版需要：6 个动词 + 契约规则表 + 三级授权 + 阶段链 + 请示机制。
用算法换掉系统之后：

| 原设计         | 现在由谁承担                         |
| ----------- | ------------------------------ |
| 契约的"分支判断"   | **Q1 阈值响应**（局部刺激自动切角色）         |
| 阶段链的"推进/巩固" | **Q4 quorum**（够强就压上，够弱就收）      |
| "什么时候撤"     | **一个脱离阈值**（损失率 or 被包围角）        |
| "谁去前排"      | **Q1**（自己长出来）                  |
| "侧翼谁掩护"     | **Q5 Voronoi 分区** + **S3 知情者** |
| "被切断怎么办"    | **§5.5 锚点分裂**（已经在算法里了）         |

**玩家只需交付三样**：

```
任务 = 区域（画一下） + 权重组（4 个数字） + 脱离阈值（1 个滑杆）
```

**分支不用写，它长出来。** 这才是人工生命，而不是把 AI 外包给一张规则表。

## 14.4 最小可玩栈（五个算法打一局）

```
S1 Boids(k-NN)  +  S3 Couzin 知情者  +  S4 ORCA
+  L0 Flow field  +  Q1 阈值响应  +  Q4 quorum
```

这五个已经能产生：自然阵型、自然角色分化、自然过窄口、自然包抄、自然溃退。
**不需要任务系统、不需要授权等级、不需要阶段机。**

## 14.5 每个算法一句话的坑

| 算法 | 坑 |
|---|---|
| Boids | 三条规则用同一半径会打架；必须分半径（§4.1） |
| k-NN | k 太小则队形散，k 太大则迟钝；6~7 是甜点，且需空间哈希加速 |
| Couzin | 知情者比例 > 20% 就退化成"全体寻路"；**低操作量靠的是少给指令** |
| ORCA | 千单位时是性能热点，需要分组算 + 只对邻近 20 个做 |
| Flow field | 目标频繁变更会导致重算风暴；要合并/节流（≥200 ms） |
| 阈值响应 | 阈值不对单位做归一化（体型/兵种）会导致大单位永远当前排 |
| Utility AI | 权重要有滞回，否则每 0.5 s 翻转；且评分项别超过 6 个 |
| Quorum | 采样率要够（每个单位都要投票），别用"全队平均"偷懒 |
| Voronoi | 动态重算 O(n log n)，只在小队锚点变化时算 |
